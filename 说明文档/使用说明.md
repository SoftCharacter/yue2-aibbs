## 1. 开始使用

### 1.1 启动软件

1. 双击 `启动器.bat`。
2. 等待主窗口出现，并等待左下角完成显卡检测。
3. 打开“设置”，确认本次功能所需模型显示“已就绪”。

启动脚本使用项目 `env` 内的 Python、FFmpeg 和 CUDA 运行组件。不要为了启动软件而随意替换系统 Python 或使用其他项目的环境。如果窗口一闪而过，保留命令窗口里的错误文字；也可在项目目录的 PowerShell 中执行下列命令，便于查看报错：

```powershell
.\env\python.exe -m app.main
```

`调试器.bat` 是进入便携环境命令行的辅助入口，不是正常使用时必须打开的窗口。

### 1.2 第一次创作：不配置大模型也能生成歌曲

1. 进入“创作歌曲”。
2. 在歌词编辑器的“载入示例…”中选择“中文 · 温暖流行”；核对风格与歌词已经填入。
3. 乐谱规划模式选择“旋律 + 和弦”，ODE 步数保持 32，生成数量设为 1。
4. 暂不启用自定义 CFG、自定义采样；音频解码选择“自动”。
5. 点击“生成歌曲”，等待完成。首次运行会加载模型，通常比后续调用多出加载时间。
6. 在结果面板播放，满意后打开作品文件夹或导出 MP3。

这条流程使用本地音乐模型。**只有让 AI 写词、改词或生成风格等功能才需要配置“大模型 API”**；你可以直接手写或导入歌词。

### 1.3 先分清三个容易混淆的操作

| 操作 | 输入／产物 | 适合什么情况 |
|---|---|---|
| 生成歌曲 | 风格、歌词，可选乐谱 → 新的人声与伴奏音频 | 从头创作或按乐谱重新演唱 |
| AI 写歌词 | 主题、篇幅、语言、要求 → 一首新歌词（可顺便生成风格描述） | 创作页从零开始写词；还需要另行生成音频 |
| AI 改歌词 | 现有歌词、修改要求 → 改写后的歌词文字 | 润色、翻译、替换段落；还需要另行生成音频 |
| AI 翻唱 | 原曲分析得到的乐谱、歌词、新风格 → 重新生成的歌曲 | 参考原曲旋律或和弦重新编曲演唱 |

当前软件的翻唱和改词流程会重新生成音频，不能承诺原伴奏、每个音高、每个字的时间位置或原歌手音色完全不变。输入参考曲也不等于声纹克隆。钢琴分声部导出是 MIDI 乐谱试听，也不是把原曲拆成人声和伴奏。

### 1.4 哪些操作需要网络

| 操作 | 网络与前置条件 |
|---|---|
| YuE2 生成、VAE 解码、SheetSage 扒谱、MERT 特征、Qwen 歌词识别 | 本地模型与环境完整时可离线运行；软件不会因缺权重而自动在线补齐 |
| 云端 AI 写词／改词／风格生成、测试连接、获取模型列表 | 请求你配置的服务，需要该服务可达；测试连接本身会实际发起一次文本请求 |
| Ollama／LM Studio 等本地文本模型 | 需要先启动相应本地服务并准备模型，服务准备好后可不依赖外网 |
| 界面内乐谱试听 | 当前实现需要联网加载钢琴音色；五线谱显示使用本地资源 |
| 导出 PDF／PNG／SVG／钢琴 WAV | 本地渲染资源与 Chromium 准备好后可离线导出，和界面内试听是不同流程 |

### 1.5 文件和模型目录

| 目录／文件 | 用途 |
|---|---|
| `models` | 本地模型权重、模型配置、随模型提供的推理程序 |
| `env` | 便携 Python 及运行依赖；FFmpeg 位于 `env\ffmpeg\bin` |
| `app` | 界面程序；正常使用不需要编辑 |
| `outputs` | 默认输出根目录，可在“设置”中更改 |
| `ui_settings.json` | 界面设置、大模型接口、近期改词要求、页面草稿等；包含接口密钥时不要分享该文件 |

## 2. 界面与常用操作

### 2.1 九个页面分别做什么

| 页面 | 主要用途 | 详细章节 |
|---|---|---|
| 创作歌曲 | 风格＋歌词生成歌曲，或只生成乐谱草稿 | 第 5 章 |
| AI 翻唱 | 载入原曲，扒谱、识别／填写歌词、重新演唱 | 第 5 章 |
| 批量生成 | 多首翻唱改词、按主题／歌词批量创作、审核与续跑 | 第 6 章 |
| 乐谱编辑 | 查看／修改 ABC，按当前乐谱生成歌曲 | 第 7 章 |
| 扒谱分析 | 提取旋律、和弦、节拍、调性、结构及 MIDI | 第 8 章 |
| 歌词识别 | 听写歌词、时间戳对齐、断句、LRC | 第 9 章 |
| 音乐特征 | MERT 帧特征、歌曲向量、层均值与相似度 | 第 10 章 |
| 作品库 | 播放、复用参数、继续任务、重新解码、管理作品 | 第 11 章 |
| 设置 | 模型状态、运行参数、大模型接口与输出位置 | 第 3 章 |

### 2.2 看不见参数时怎么办

页面中的“高级采样参数”“音频解码设置”等卡片默认可能折叠，点击标题展开。较长页面可以在所在区域滚动；参数也可能因为模式变化而隐藏或变灰。

- **隐藏／变灰**通常表示当前模式不使用该参数。例如自动解码不使用手填的分块长度。
- 卡片标题或参数名称旁的 `ⓘ` 可悬停查看解释。
- 切到其他页面不会同时开启第二个主模型任务；运行按钮会提示等待当前任务。
- 软件会记住部分页面输入；“自动记住页面输入”和“保存完整任务草稿”不是一回事，重要内容请明确保存，见第 11、13 章。

### 2.3 播放器

| 控件 | 如何使用 |
|---|---|
| ▶／暂停 | 播放或暂停当前音频；启动另一个普通音频播放器时，会暂停正在播放的另一个普通播放器 |
| 波形 | 点击某个位置跳转到相应时间；它是定位辅助，不是音频剪辑工具 |
| 当前时间／总时长 | 用于核对播放位置与实际音频长度 |
| 音量滑块 | 0～100，初始 85；只改变试听音量，不会改写音频文件或导出的响度 |

没有音频的草稿不能播放。乐谱预览里的钢琴试听有独立控件，与上述音频播放器不同，见第 7 章。

### 2.4 进度、停止、日志和快捷键

| 操作 | 说明 |
|---|---|
| 页面“停止”／底部“取消” | 请求停止当前任务；通常等待当前模型调用或检查点后生效，不是立刻强杀进程 |
| “日志”或 `Ctrl+L` | 打开／收起运行日志，排查加载、推理或导出问题 |
| 日志“清空” | 只清除界面显示的日志，不删除作品 |
| `Ctrl+Enter` | 执行当前页面的主要操作；使用前先确认所在页面和输入 |
| `Ctrl+Z` | 文本编辑器撤销；歌词清空和应用 AI 改写支持撤销。不要假定载入示例／载入作品等所有替换动作都能撤销 |
| 左下角显卡信息 | 显示检测到的 GPU 和当时显存占用；不是本次任务的固定内存需求预测 |

任务停止后查看提示和保存阶段。已经完成的阶段可复用；正在生成的一半歌曲 token、尚未结束的声学步骤等，不一定有可续用的完整结果。

## 3. 设置：模型、运行环境与大模型 API

### 3.1 模型文件状态

模型表的“已就绪”表示程序检查到了配置和权重文件；不等同于已经对所有权重做过完整哈希校验。“显存中”的标记表示程序当前持有该模型实例。

| 模型 | 哪些功能需要 |
|---|---|
| YuE2-3B | 歌曲生成、乐谱规划、按乐谱生成 |
| YuE2-Vae | 将声学潜变量变成 48 kHz 双声道音频；也用于重新解码 |
| SheetSage2 | 扒谱、参考原曲旋律／和弦的翻唱、部分歌词分段流程 |
| MERT-v2-FullSong | 整曲音乐特征；SheetSage2 的主干依赖 |
| MERT-v2-30s | 以 30 秒上下文提取音乐特征 |
| Qwen3-ASR-1.7B | 歌词识别，包括批量翻唱中的歌词听写 |
| Qwen3-ForcedAligner-0.6B | 歌词时间戳对齐；关闭对齐的纯识别不需要加载它 |

“卸载全部模型并释放显存”只卸载程序当前加载的模型，不删除模型文件。主任务运行时需要先等待任务结束或停止。

### 3.2 运行设置逐项说明

| 参数 | 选项／范围与初始值 | 含义及使用方法 |
|---|---|---|
| 主题 | 浅色／深色，初始浅色 | 保存后重启软件生效 |
| 计算设备 | 自动（优先 CUDA）／CUDA 显卡／CPU，初始自动 | 有兼容显卡时选自动或 CUDA；CPU 会很慢。显式选 CUDA 但设备不可用会报错 |
| YuE2 显存预算 | 界面可填 0～200 GiB，整数，初始 0 | 0 表示按整张显卡处理；生成／规划时非零值至少为 4 GiB，否则拒绝运行。预算中预留约 2 GiB，不是全部用于模型；低预算可能导致显存不足。预算不能创造物理显存，也不代表对所有其他分析模型统一限额 |
| YuE2 解码后端 | `torch + CUDA Graph（快）`／`torch-eager（兼容模式）`，初始前者 | 这里影响 YuE2 token 生成运行方式，不是把 FLAC 转成 MP3。遇到 CUDA Graph 兼容错误可切 eager 后重试新任务 |
| 注意力内核 | 自动检测／cuDNN／SDPA 通用，初始自动 | 通常保持自动。**同时决定“声学合成”阶段的注意力**：自动／cuDNN 时显存占用最低（整首歌峰值约 9～10 GiB）；选 SDPA 通用时声学合成改为分块计算，显存略高、速度较慢。特定内核报兼容错误时再尝试 SDPA。最终使用的内核可在“环境信息”的“注意力内核”“声学合成注意力”两行及日志查看 |
| 音频解码器 VAE | 本地解码器列表，通常 `YuE2-Vae` | 影响潜变量到音频的解码；未找到模型时列表也可能显示兜底名称，因此名称出现不保证文件完整，以模型状态和运行校验为准。legacy 用途按随附模型说明核对，不要把它当作必备模型 |
| MP3 导出码率 | 320k／256k／192k／128k，初始 320k | 数值较高通常文件较大；只作用于 MP3 导出，不改变原 FLAC 或模型生成质量 |
| 加载 YuE2 时校验权重 SHA256 | 开／关，初始关 | 开启后检查相关权重完整性，会增加加载时间；适合排查下载不完整或文件损坏 |
| 运行某个模型前自动卸载其他模型 | 开／关，初始开 | 用切换时重新加载的代价降低多个模型同时占显存的风险；关闭后可能增加显存压力 |
| 输出目录 | 可手填或“浏览…”选择，初始留空 | 留空使用项目 `outputs`；手填后离开输入框才提交。改目录影响新结果和作品／批次列表扫描，不会自动移动旧文件 |

修改这些设置通常在下次任务或模型加载时应用，不能改变已经开始的推理。继续已有任务时，保存下来的设备／模型／后端等运行选择可能被沿用；**当前显存预算仍用于恢复和解码**，详见第 11 章。对于本机 RTX 5090，第一次使用可以先保持自动设备、预算 0、自动内核与自动卸载，出现具体资源问题再调整。

“环境信息”会显示 Python、PyTorch、CUDA、GPU、FFmpeg 和模型目录等信息。反馈问题时可复制这些信息和报错文字，但不要附带 API Key。“关于”区域提供项目和许可提示；如需分发模型，应另行阅读模型随附许可文件。

### 3.3 配置 AI 写词／改词接口

1. 打开“设置 → 大模型 API（AI 写歌词 / 改歌词 / 风格）”。
2. 选择对应预设；如果使用自建网关，选择“自定义（OpenAI 兼容）”。
3. 填入服务要求的接口地址、API Key 和实际可用的模型名称。
4. 等待输入保存，或直接点击“测试连接”。这些输入会自动保存，没有另外的“保存 API”按钮。
5. 看到成功回复后，再到歌词框执行一次短小的改写，确认该模型能够按歌词格式输出。

| 参数／按钮 | 初始值或行为 | 使用说明 |
|---|---|---|
| 服务商预设 | 提供 DeepSeek、通义千问、Kimi、智谱、硅基流动、火山方舟、OpenRouter、OpenAI、Anthropic Claude、Ollama、LM Studio、自定义 | 预设只填入协议、地址和示例名称，不代表账户已开通或示例模型目前对你可用。切换后检查地址、模型和 Key 是否属于同一服务 |
| 接口地址 Base URL | OpenAI 兼容服务常形如 `https://api.example.com/v1` | 填服务提供的兼容入口，不是网页聊天地址。程序会使用聊天完成接口；不要凭示例猜测自建服务端口 |
| API Key | 初始为空；可点眼睛显示／隐藏 | 云服务通常需要正确密钥；明确配置的本地无鉴权服务可留空。填写后会保存在本机 `ui_settings.json`，不是加密保险库 |
| 模型名称 | 取决于预设，可手填／下拉选择 | 必须是当前接口支持的准确模型标识；不要直接填写本地 YuE2 权重目录，除非对应文本服务本身就是这样命名 |
| 获取模型列表 | 从当前接口读取列表 | 列表读取失败不一定表示聊天不可用，某些网关不提供列表；可按服务说明手填模型再测试 |
| 温度 | 0.0～2.0，初始 0.8 | 影响文字改写的随机性，和第 4 章音乐采样温度互相独立。要求保守修订时可降低，追求多种表达时可提高；部分模型／协议可能忽略它 |
| 系统提示词：写歌词 | 内置“作词人”提示 | 用于创作页“📝 AI 写歌词”和批量创作按主题写词。规定只输出歌词、段落标签、每行长度、结构完整、按【篇幅】控制行数等长期要求；本次写什么（主题、语言、篇幅、其他要求）在写词弹窗或批量页填写 |
| 系统提示词：改歌词 | 内置“歌词编辑”提示 | 用于各页面“✨ AI 改歌词”、批量翻唱改词、批量创作润色导入歌词，以及审核时按意见修改。规定只输出完整歌词、未要求修改的部分保持原样、遵守【约束】结构要求等；自定义时不要删掉对【约束】的遵守说明，否则结构模式会失效 |
| 系统提示词：风格描述 | 内置“音乐制作人”提示 | 用于写词弹窗“同时生成风格描述”和批量“AI 生成风格”。要求只输出一行英文风格标签；程序只取回复的第一行 |
| 恢复默认 | 每个标签页各有一个，只恢复该页提示词 | 不会清除当前地址、Key、模型，也不影响另外两套提示词 |
| 测试连接 | 实际请求模型回复一段测试文字 | 用于检查地址、权限和模型；不是只做网络 ping，云服务可能计入用量。修改提示词不会让已有的测试结果失效 |

三套提示词分别保存；与默认内容完全相同（或清空）时按“未自定义”保存，以后程序改进默认提示词时会自动使用新版本。程序发给模型的请求内容用【主题】【篇幅】【歌词语言】【歌曲风格】【其他要求】【当前歌词】【修改要求】【约束】【歌词】【已知信息】【风格参考】等小标题分段，自定义提示词可以直接引用这些小标题。

如果你从未配置接口，AI 写词／改词／需要 AI 的批量步骤会提示先配置；直接手写歌词生成歌曲不受影响。

**本地服务示例**：先在本地文本模型工具中启动兼容 API 服务，再在本软件选择对应预设或自定义，填写该工具显示的地址和模型名。软件不会替你启动 Ollama／LM Studio 服务，也不会替文本服务下载模型。

**Claude 原生协议**：只有选择 Anthropic 预设时才使用该协议，依赖环境中的 `anthropic` 包。若提示缺少 SDK，需先在项目环境补齐相应依赖；本手册编写时该包尚未安装。使用能提供 OpenAI 兼容接口的网关，应按网关协议选择自定义，而不是仅凭模型名称含 Claude 就选原生协议。

### 3.4 AI 改歌词对话框：所有选项

在歌词框上方输入修改要求后回车，或点击“✨ AI 改歌词”。若入口中已经填了要求，弹窗打开时会立即开始生成；想先调整弹窗选项，可以先留空要求打开弹窗，再填写并点击“生成”。改歌词使用“改歌词”系统提示词。

歌词框为空时：创作页会改为打开第 3.5 节的“AI 写歌词”弹窗；翻唱、乐谱编辑、歌词识别等页面只提示先填写、导入或识别歌词，不会凭空写词。

| 控件 | 如何使用及影响 |
|---|---|
| 告诉 AI 怎么改 | 写清修改范围、内容和保留项。例如“只改副歌，改为清晨出发主题，保留两段主歌及各段行数” |
| 快捷要求 | 点击填入一条常用要求，如更押韵、改成粤语、翻译成英文、增加桥段等；可继续手工修改，不会单独替你完成生成 |
| 历史补全 | 输入时可选择近期要求；程序保留最近约 30 条不同要求 |
| 结构：不限制结构 | 可增删段落和行数，适合重写；对已有旋律的贴合可能变差 |
| 结构：保持段落和行数 | 要求段落标签顺序与每段行数一致，允许每行长度调整；翻译时可先用此模式 |
| 结构：保持段落、行数和每行字数 | 对应行的长度也尽量接近，适合同语言改词后再翻唱；这是提示约束，不是音符与歌词自动逐字对齐保证 |
| 附带歌曲风格描述 | 当前页面有风格时默认勾选；勾选后把风格作为改词上下文，未提供风格时不可选 |
| 当前歌词（左侧） | 只读对照；开始时取打开弹窗那一刻的歌词 |
| AI 修改结果（右侧） | 实时显示返回文字。**生成进行中为只读**，结束（完成、出错或停止）后才能手工修改，避免手改内容被随后到达的结果覆盖。完成后会自动整理：去掉思考过程和代码块标记、去掉开头的歌名行，完全没有段落标签时整体标为 `[Verse]`。如果整理后没有任何要唱的歌词行（例如只返回了歌名或只有段落标签），会清空结果并提示“模型返回了空内容” |
| 生成 | 根据左侧当前歌词和新要求生成；再次生成会清空右侧，想保留该版请先复制或应用 |
| 停止 | 取消本次请求。已收到的文字按上面的规则整理后保留（没收完的思考过程也会去掉）；整理后仍有歌词行才能“应用”或“继续改”，但内容可能不完整，应用前请核对 |
| 在结果上继续改 | 把右侧内容作为新的左侧基稿，清空本次要求，再提出下一轮修改；不会自动发起下一轮 |
| 应用到歌词 | 把右侧当前文字写回原页面，不会生成歌曲音频；写回后可在原歌词编辑器 Ctrl+Z 撤销。右侧被手动清空、或只剩段落标签时，会提示“歌词是空的”并拒绝应用，页面原歌词不会被清掉 |
| 取消／关闭弹窗 | 不应用右侧结果；正在进行的请求会收到取消请求 |

不同入口的结构初值不同：创作页为“不限制结构”；翻唱、乐谱编辑、歌词识别页为“保持段落、行数和每行字数”；批量审核继承批次模式。**请以弹窗当前选中的值为准。** 手工改词和 AI 改词都应再检查同音字、段落、行数和演唱节奏；交互弹窗不像批量流程那样自动反复做结构重试。

### 3.5 AI 写歌词对话框（创作页）

创作页歌词框上方有“📝 AI 写歌词”按钮。也可以在歌词为空时，把主题直接写进上方输入框后回车，弹窗会带着这个主题打开（不会自动开始，确认选项后点“开始写”）。写歌词使用“写歌词”系统提示词，风格使用“风格描述”系统提示词。

| 控件 | 如何使用及影响 |
|---|---|
| 主题／故事 | 必填。可以是一句主题，也可以是一小段故事，例如“毕业那天在操场告别，约定十年后再见” |
| 歌词语言 | 默认“由 AI 按主题决定”（不发送语言要求）；可选中文、粤语、英文、日语、韩语，也可以直接输入其他语言或方言 |
| 篇幅 | 约 1／2／3／4 分钟，默认约 3 分钟。每档对应一套段落安排和行数，作为【篇幅】发给模型（见下表）。篇幅是**目标**，不是保证：YuE2 的歌曲长度主要由歌词长度决定，实际时长还受旋律、间奏、语言和歌曲生成上限（第 4.4 节“最大 tokens”）影响。程序不会为了匹配篇幅自动修改你的采样参数；如果调低过最大 tokens，长篇幅的歌仍可能被截断 |
| 其他要求 | 可选，例如“副歌押韵好记；用第一人称”。下方快捷按钮点击后**追加**一条要求，已有的不会重复 |
| 参考当前风格描述写词 | 页面已填写风格时默认勾选，把风格作为写词参考（例如 rock 会写得更有力量）；页面没有风格时不可用 |
| 同时生成风格描述 | 页面风格为空时默认勾选。歌词写完后再请求一次模型，生成一行英文风格标签，显示在下方“风格描述”框，可手动修改；应用时填入页面的风格框。风格生成失败不会丢掉已写好的歌词，可手动填写风格 |
| 开始写／停止 | 流式显示歌词。停止或出错时，已收到的部分会整理后保留（去掉思考过程——包括还没收完的、代码块标记和开头的歌名行）；整理后仍有歌词行时可以应用 |
| 生成的歌词 | 完成后自动去掉开头的歌名行；完全没有段落标签时整体标为 `[Verse]`，状态栏会说明。只返回歌名或只有段落标签时视为空内容，不能应用。**生成进行中（包括歌词已显示、风格还在生成时）歌词框和风格框都是只读的**，全部结束后才能手动修改，避免手改内容被后台结果覆盖 |
| 应用 | 用结果**替换**创作页的全部歌词（可在歌词框 Ctrl+Z 撤销）；勾选了“同时生成风格描述”且风格不为空时，同时替换页面风格 |
| 取消 | 不修改页面；正在进行的请求会被取消 |

各档篇幅发给模型的段落安排（批量创作的“歌词篇幅”使用同一套）：

| 篇幅 | 段落安排 | 目标行数 |
|---|---|---|
| 约 1 分钟 | `[Verse]` 4 行 + `[Chorus]` 4 行 | 约 8～10 行 |
| 约 2 分钟 | `[Intro]` + `[Verse]` 4 行 + `[Chorus]` 4 行 + `[Verse]` 4 行 + `[Chorus]` 4 行 + `[Outro]` | 约 16～20 行 |
| 约 3 分钟，默认 | `[Intro]` + 主歌 + 导歌 + 副歌 + 主歌 + 导歌 + 副歌 + `[Bridge]` + 副歌 + `[Outro]`；主歌各 6 行、副歌各 4 行、导歌和桥段各 2 行（合计 30 行） | 约 28～34 行 |
| 约 4 分钟 | `[Intro]` + 主歌 + 导歌 + 副歌 + 主歌 + 导歌 + 副歌 + `[Instrumental]` + `[Bridge]` + 副歌 + 副歌 + `[Outro]`；主歌、副歌各 6 行，导歌和桥段各 2～4 行（合计 42～48 行） | 约 40～50 行 |

模型不一定严格按行数写，请看状态栏报告的实际行数。写好之后如果只想局部调整，用“✨ AI 改歌词”在现有歌词上继续改，比重新写一首更可控。

## 4. 共用输入与生成参数详解

### 4.1 风格描述与标签库

风格用于描述流派、人声、乐器、情绪、演唱语言和速度。输入框会显示字符计数，生成风格描述上限为 **1000 字符**。将意图写成一组清晰标签，比堆砌大量互相矛盾的要求更容易检查和复用。

```text
Mandarin, acoustic pop, warm female vocal, piano, acoustic guitar, hopeful, mid-tempo
```

标签库只是快捷填写：点击中文标签，把对应英文加入文本；已有的同名英文标签不会重复加入。标签不是硬性开关，模型不保证每项都严格实现。

| 类别 | 当前可选标签 |
|---|---|
| 流派 | 流行、摇滚、民谣、爵士、放克、迪斯科、R&B、嘻哈、电子、合成器流行、Lo-fi、金属、抒情、国风、古典、乡村、朋克、灵魂乐、City Pop |
| 人声 | 女声、男声、温暖人声、有力人声、气声、沙哑、合唱、对唱、说唱 |
| 乐器 | 钢琴、木吉他、电吉他、贝斯、鼓、弦乐、合成器、电钢琴、萨克斯、小号、管风琴、二胡、古筝、笛子、808 |
| 情绪 | 欢快、伤感、激昂、梦幻、浪漫、史诗、温暖、黑暗、放松、怀旧 |
| 语言 | 中文、粤语、英语、日语、韩语 |
| 速度 | 慢速、中速、快速 |

例如要女声钢琴流行歌，可先点“流行、女声、钢琴、温暖、中文、中速”，然后删改成自己满意的描述。想让歌词成为英文，应同时提供英文歌词或执行翻译；只把风格标签改成 English 不是可靠的歌词翻译操作。

### 4.2 歌词格式与编辑器工具

歌词生成输入最多 **12000 字符**，并不等于最多 12000 个实际演唱字。段落标签单独一行，每句单独一行，段落间空一行。纯器乐段落可以只留标签。

```text
[Intro]

[Verse]
清晨的风轻轻吹来
我把心愿装进行囊

[Chorus]
向着远方慢慢出发
让这首歌陪我成长

[Outro]
让这首歌陪我成长
```

| 标签／工具 | 作用 |
|---|---|
| `[Intro]` 前奏 | 开场段落 |
| `[Verse]` 主歌 | 叙述情节或铺陈情绪 |
| `[Pre-Chorus]` 导歌 | 从主歌过渡到副歌 |
| `[Chorus]` 副歌 | 主要旋律、主题句或重复部分 |
| `[Bridge]` 桥段 | 与主副歌形成变化的段落 |
| `[Instrumental]` 间奏 | 器乐段落 |
| `[Solo]` 独奏 | 提示独奏段落 |
| `[Outro]` 尾奏 | 收尾段落 |
| 点击段落按钮 | 在光标所在行附近插入标签和换行；插入后检查位置是否符合你的结构 |
| 字符／行数／段落计数 | 帮助检查长度和标签，不能据此精确计算成歌时长 |
| 载入示例 | 选择内置中文流行、英文 synth-pop、英文 indie folk、中文放克迪斯科等示例；部分页面还会同步填入示例风格，会替换当前内容，重要草稿先保存 |
| 导入 | 读取 TXT／LRC。优先 UTF-8，也兼容常见中文编码；LRC 时间戳与元信息会去除，得到普通歌词，不会恢复原识别时间轴 |
| 清空 | 清空当前歌词文字；可 Ctrl+Z 撤销 |
| ✨ AI 改歌词 | 使用第 3.4 节的改词弹窗；歌词为空时，创作页改为打开 AI 写歌词，其他页面提示先填写歌词 |
| 📝 AI 写歌词 | 仅创作页有，使用第 3.5 节的写词弹窗 |

### 4.3 生成设置

| 参数 | 范围／初始值 | 含义与调整方法 |
|---|---|---|
| 乐谱规划模式：旋律 + 和弦 | 常规创作初始模式 `full` | 先规划旋律与和弦再生成；适合想获得可编辑乐谱的创作 |
| 乐谱规划模式：仅旋律 | `melody` | 规划／使用旋律，和弦约束较少；翻唱入口有额外含和弦确认，见第 5 章 |
| 乐谱规划模式：不使用乐谱 | `off` | 直接生成歌曲 token，不先写乐谱；没有可用于“仅生成乐谱”的规划结果 |
| 渲染质量（ODE 步数） | 8～64，初始 32；快捷 16／32／48 | 声学合成计算步数。更多步数通常更慢，质量变化依赖样本；不是把音频从低码率升级为高码率，也不是歌曲长度 |
| 随机种子 | 0～9223372036854775807，常规初始 42 | 固定种子用于比较参数；相同输入、模型和运行环境下便于复现。跨设备／后端／版本不承诺逐采样点完全一致 |
| 骰子 | 立即填入一个随机种子 | 只改变当前种子数值，不会自动开始生成 |
| 每次随机 | 常规初始关 | 每次开始生成前换种子；批量页称“每首随机”，详见第 6 章。保存草稿本身不会随机换种子 |
| 生成数量 | 1～16，初始 1 | 一次生成多个版本，种子以基准值依次 +1；通常顺序处理，不是并行跑 16 个模型。批量页表示“每首的版本数” |
| 文本引导 CFG：自定义 | 初始不勾选 | 不勾选沿用当前模型默认：有乐谱模式 1.0，不使用乐谱模式 1.01；数值框显示 1.2 不代表未勾选时也使用 1.2 |
| CFG 数值 | 0.00～20.00，自定义框初始 1.20 | 改变条件引导强度。提高可能强化条件，也可能让结果不自然；先比较默认和 1.2 这样的小幅变化，不把极大值当成“更好” |
| 作品名 | 可选 | 用于标识作品与作品库展示；不是给模型增加歌词，也不是在已有音频中唱出这个名字。某些页面不展示该输入 |

不同页面可能只显示这些参数的子集。特别是只生成乐谱每次输出一份计划，生成数量不是批量产生多份乐谱草稿的开关。

### 4.4 高级采样：两个阶段、七种参数

先展开“高级采样参数”。**未勾选“启用自定义采样”时，下面的数值不作为自定义覆盖传入。** 勾选后，乐谱规划和歌曲生成两列分别控制 ABC token 与音乐 token。点击“恢复默认”会恢复两列数值，**不会自动取消“启用自定义采样”**。

| 参数 | 可调范围 | 乐谱规划初始值 | 歌曲生成初始值 | 含义与影响 |
|---|---|---:|---:|---|
| 温度 Temperature | 0.000～5.000 | 0.700 | 1.000 | 控制采样随机程度。较低偏保守，较高变化更大；0 使用最大得分选择，此时 Top-p／Top-k 不再按随机采样方式起作用 |
| Top-p | 0.010～1.000 | 0.900 | 0.950 | 只从累计概率达到阈值的一组候选中采样；较低限制候选更多，1 不做此项概率截断 |
| Top-k | 1～1000 | 30 | 100 | 保留得分较高的前 K 个候选；较小更集中，较大可选内容更多 |
| 重复惩罚 | 0.500～3.000 | 1.005 | 1.200 | 对近期重复 token 的倾向作调整。1 不施加此项惩罚，大于 1 通常抑制重复，小于 1 可能鼓励重复；过高可能破坏合理的副歌重复与节奏 |
| 最小 tokens | 乐谱 0～4096；歌曲 0～9000 | 32 | 200 | 在达到数量前阻止正常结束。过高可能造成拖长或重复；不是“至少唱完多少汉字”的参数 |
| 最大 tokens | 乐谱 1～4096；歌曲 1～9000 | 4096 | 9000 | 当前阶段的生成上限。达到上限可能截断；它不是精确指定最终时长的设置 |
| 惩罚窗口 | 1～100 | 100 | 50 | 重复惩罚查看最近多少个 token；只看该窗口内的历史，不是按歌词行数计算 |

**最小值不得超过最大值。** 界面会联动约束最大值下限；例如想把歌曲最大 tokens 从 9000 调到 128，应先把最小 tokens 降到 128 或更低。

歌曲 token 约 **25 个对应 1 秒音频**，因此可以估算上限：

| 歌曲最大 tokens | 约对应的时长上限 |
|---:|---:|
| 750 | 30 秒 |
| 1500 | 1 分钟 |
| 3000 | 2 分钟 |
| 4500 | 3 分钟 |
| 9000 | 6 分钟 |

这个换算只用于“歌曲生成”一列，不适用于 ABC 乐谱 token，也不能保证歌曲正好在指定秒数结束。想让歌曲自然结束，歌词结构、乐谱和 token 上限要相互配合；为了短测试而强压上限，结尾可能突然截断。

没有乐谱规划的流程不会使用 ABC 采样参数；按已有完整 ABC 生成时，修改 ABC 规划温度也不会自动重写这份乐谱。

### 4.5 音频解码设置

音频解码把模型生成的潜变量变成最终可播放音频。这里的分块参数主要用于控制解码内存占用，不改变歌词、乐谱或声学模型已经生成的内容。

| 参数 | 范围／初始值 | 用法 |
|---|---|---|
| 自动（默认） | 初始选择 | 当前实现自动使用分块策略：有效预算不超过 12 GiB 时通常取 512 帧，否则 1024 帧，上下文 16 帧；预算 0 按实际设备／内存预算解析，不等于有效预算为零 |
| 分块解码 | 手工模式 | 使用下面的分块长度和上下文；适合需要明确控制解码峰值的情况 |
| 完整解码 | 一次处理整段 | 长音频可能需要更多显存；不是开启了就必然比合理分块听感好 |
| 分块长度 | 64～8192 帧，初始 1024 | 每块保留的有效潜变量帧数。较小通常更省峰值内存，但块数增多；只有手工分块模式使用此框 |
| 上下文长度 | 12～256 帧，初始 16 | 每块前后额外参考的帧数，减少分块边缘影响；当前 VAE 至少 12 帧。更大需要额外计算和内存 |

潜变量同样约 25 帧／秒，1024 帧约 40.96 秒，512 帧约 20.48 秒。解码按块检查停止；完整解码中的一次模型调用可能要结束后才能响应停止。如果歌曲已经有合法 `latent.npy`，可以只重新解码，见第 11 章。

### 4.6 怎样有条理地调参数

1. 先用默认值生成一个版本，记录风格、歌词、种子和结果。
2. 固定种子，每次只改一类参数，例如先换风格，或只比较 ODE 16 与 32。
3. 想探索不同旋律／唱法，先保持其他参数不变，换种子或生成多个版本。
4. 想解决结尾截断，先检查最大 tokens 和歌词长度，不要先提高 CFG。
5. 显存不足先确认发生在生成阶段还是 VAE 解码阶段，再决定卸载模型、改预算或使用分块解码。

参数没有对所有歌曲都最佳的一组值。数值范围表示界面允许输入的边界，不表示极值都适合正常创作。

## 5. 创作歌曲与 AI 翻唱

### 5.1 创作歌曲：从风格和歌词生成歌曲

“创作歌曲”页适合从文字开始创作。左侧依次填写风格描述、歌词和生成设置，右侧查看进度、音频、乐谱和生成信息。完整生成的主音频保存为 48 kHz、双声道、24 位 FLAC。

#### 5.1.1 输入区与参数的用途

| 控件 | 填写和操作方法 | 本页行为与限制 |
|---|---|---|
| 风格描述 | 描述流派、人声、乐器、情绪、演唱语言等；也可展开风格标签库点击添加。 | 必填，提交时不得超过 1,000 字符。标签库的全部分类与添加规则见第 4 章。 |
| 歌词 | 用 `[Verse]`、`[Chorus]` 等组织段落，每行一句；支持手动输入、导入、段落标签按钮及 AI 改歌词。 | 必填，提交时不得超过 12,000 字符。歌词长度和结构会影响成歌长度，但不能据此指定精确时长。公共歌词工具见第 4 章。 |
| 载入示例… | 在歌词框下方选择内置示例。 | 会同时替换本页的歌词和风格描述，不会替换生成设置；已有内容需要保留时先保存草稿。 |
| 乐谱规划模式 | 选择“旋律 + 和弦”“仅旋律”或“不使用乐谱”。 | 前两种先形成可查看的乐谱；“不使用乐谱”直接生成歌曲，没有可送去编辑的 ABC 乐谱。 |
| 渲染质量、随机种子、生成数量、文本引导 CFG、作品名 | 按第 4 章设置。 | 数量为 1～16 首，同一组文字生成多个版本，种子逐首加 1；作品名用于结果和作品库显示。 |
| 高级采样参数 | 按需分别控制乐谱规划与歌曲生成的采样。 | “仅生成乐谱草稿”只执行规划；歌曲采样、ODE 和音频解码设置留待后续生成使用。 |
| 音频解码设置 | 选择自动、分块或完整解码。 | 只影响最终音频解码；各参数、范围及显存关系见第 4 章。 |

内置示例包括“中文 · 温暖流行”“English · Dreamy synth-pop”“English · Indie folk”“中文 · 放克迪斯科”。没有已保存的创作页输入时，程序初次进入本页会填入第一组中文示例。示例是可编辑的风格与歌词，不含预先生成好的音频。

#### 5.1.2 全部操作按钮

| 按钮 | 用途 | 结果与注意事项 |
|---|---|---|
| 保存草稿 | 将当前风格、歌词及整套生成参数保存为独立草稿任务。 | 每次创建新草稿目录，可在作品库载入或继续；保存本身不生成乐谱或音频。可以先保存尚未写完的输入，生成前仍需补齐必填项。 |
| 载入草稿 | 选择一份草稿或作品的文件夹。 | 有 ABC 乐谱时转到“乐谱编辑”页；没有乐谱时将参数填回创作页。载入不自动续跑旧任务。 |
| 仅生成乐谱草稿 | 使用当前风格、歌词、种子和乐谱采样参数先规划乐谱。 | 只生成一份规划，不生成音频；即使“生成数量”大于 1，本操作也只规划一次。完成后通常转到乐谱编辑页。 |
| 生成歌曲 | 使用当前输入创建新歌曲任务并完成生成。 | 执行至音频完成；生成数量大于 1 时顺序生成多个版本。快捷键 `Ctrl+Enter` 在本页触发此操作。 |
| 停止 | 请求取消正在运行的后台任务。 | 完整保存的阶段可以继续；当前尚未保存完的阶段不能按逐 token 或逐步进度恢复。详见第 11 章。 |

选择“不使用乐谱”后点击“仅生成乐谱草稿”，程序会要求改用“旋律 + 和弦”或“仅旋律”。普通“生成歌曲”则可以使用“不使用乐谱”。

规划期间如果修改了本页输入，或者在乐谱编辑页载入/修改了另一首作品，完成的规划仍会保存，但不会自动覆盖这些新输入。出现“乐谱已保存；输入或编辑中的作品已变更，未自动载入”时，到作品库载入刚保存的规划即可。

#### 5.1.3 示例操作：先看谱，再生成一首中文歌曲

1. 在“创作歌曲”的“载入示例…”中选择“中文 · 温暖流行”，检查风格和歌词。
2. 选择“旋律 + 和弦”，先将“生成数量”设为 1。其余生成参数可保留当前默认值。
3. 点击“保存草稿”，保留当前文字和参数；再点击“仅生成乐谱草稿”。
4. 规划完成后，在“乐谱编辑”页检查 ABC 与实时预览，按第 7 章修改需要调整的内容。
5. 完全沿用规划及保存参数时，可用“生成设置”中的“继续已保存任务”；修改过乐谱、歌词、风格或参数时，点击“按此乐谱生成”创建新任务。
6. 完成后在右侧试听，使用“打开文件夹”“导出 MP3”或“导出乐谱”，也可到作品库继续管理。

如果希望直接听到初稿，第 3 步改点“生成歌曲”即可。以后在结果中点击“编辑乐谱再生成”，仍可进入改谱流程。

### 5.2 AI 翻唱：沿用旋律，生成新的编曲与演唱

AI 翻唱的流程是“源音频 → 扒取 ABC 旋律 → 整理歌词 → 目标风格 → 按乐谱生成”。实际送入歌曲生成器的是风格、歌词和 ABC 乐谱，源音频主要用于前面的扒谱、歌词识别及来源记录。

这里的翻唱会重新生成歌声与伴奏，不提供原人声分离、原伴奏原样保留、指定人物声纹克隆或逐采样对齐原曲的功能。音色、节奏处理、结构和演唱表现可能与原录音不同；选择目标人声标签也不是上传某个人的声音进行克隆。

#### 5.2.1 第 1 步：载入源歌曲并扒谱

| 控件 | 用法 | 实际行为 |
|---|---|---|
| 音频拖放区 | 拖入音频，或点击选择文件。 | 文件选择器列出 MP3、WAV、FLAC、M4A、AAC、OGG、OPUS、WMA，以及 MP4、MKV 等容器；能否读取还取决于文件本身和解码器。 |
| 源歌曲播放器 | 试听当前选中的录音。 | 播放、定位、音量等公共操作见第 2 章。选择文件不会自动扒谱或识别歌词。 |
| 仅旋律（去掉和弦符号，翻唱推荐） | 默认勾选，决定这次扒谱是否输出只保留旋律的 ABC。 | 勾选/取消时也会把第 5 步的生成模式切到“仅旋律”/“旋律 + 和弦”。它不会立即修改已经存在的乐谱文本。 |
| 扒取旋律 | 对当前源歌曲运行 SheetSage2。 | 需要真实存在的源文件；完成后填入 ABC，并显示调性、估计 BPM、音符数量和输出目录。 |

翻唱页的扒谱入口使用简化设置。若要设置扒谱预设、时长范围或其他分析参数，请在“扒谱分析”页执行，再使用该页的发送入口复用结果，详见第 8 章。

扒谱后记录的原曲段落结构可供本页歌词识别复用。换成另一首源音频时，旧段落结构会清除，旧的乐谱和歌词文本则保留，以免丢掉手工修改；这也意味着换文件以后必须检查第 2、3 步是否仍属于同一首歌。

若在扒谱期间更换源歌曲或修改 ABC，完成结果会保存到扒谱输出目录，但不会写回当前编辑器。状态栏会显示“结果已保存，未填入”及目录。若模型完成了部分分析却没有产生 ABC，也不能直接生成翻唱，需要检查错误提示，重新扒谱或自行导入乐谱。

#### 5.2.2 第 2 步：检查或自行提供 ABC

本页可以跳过源音频和扒谱，直接粘贴 ABC，或点击 ABC 编辑器的“打开”导入 `.abc` / `.txt` 文件。只要备齐非空乐谱、风格和歌词，就可以生成翻唱；仅为了生成歌曲而提供已有乐谱时，不强制要求上传原音频。

ABC 工具包括“打开”“另存为”“去掉和弦”，详细规则见第 7.2 节。来源提示会标明它是从哪首录音扒出的，或者显示“手动导入”的文件名。生成时 ABC 文本不得超过 100,000 字符。

右侧“乐谱预览”用于看谱和试听旋律。右侧已经选中了某个生成结果时，预览显示的是该结果的乐谱；不要把它误认为始终显示左侧刚修改的 ABC。完成一次新的扒谱或载入扒谱结果后，右侧会切回显示这份输入乐谱。

#### 5.2.3 第 3 步：整理或识别原曲歌词

| 控件 | 用法与效果 |
|---|---|
| 语言 | 默认“自动识别”；也可选中文、粤语、英语、日语、韩语、法语、德语、西班牙语、俄语、葡萄牙语、意大利语、泰语、越南语或印尼语。此项指定歌词识别的演唱语言，不会翻译歌词，也不会改变目标风格中的语言标签。 |
| 识别原曲歌词 | 使用第 1 步的源文件执行 Qwen3-ASR 识别及强制对齐，整理后替换当前歌词。已有歌词时先询问是否覆盖。 |
| 歌词文本与公共工具 | 按原曲演唱顺序校对字词和重复段落，添加对应的 `[Verse]`、`[Chorus]` 等标签。段落按钮、导入、清空、AI 改歌词见第 4 章。翻唱页没有歌词示例下拉框。 |

已经对当前这首源音频扒谱，且有有效段落结构时，“识别原曲歌词”会直接利用这些段落加标签；没有可复用结构时按识别到的停顿等信息整理，不会为了这一次识别自动再运行扒谱。此入口固定进行时间对齐，断句的停顿阈值和行长采用内置默认值；需要自定义这些设置时使用“歌词识别”页。

识别结果会保存到歌词输出目录，包括整理后的文本、原始识别文本、时间歌词和识别详情。填入编辑器后可按 `Ctrl+Z` 撤销本次替换。若识别期间换了源音频或编辑了歌词，新识别结果仍保存到文件，但不覆盖当前内容。

本页的“AI 改歌词”会带入目标风格，并默认请求保持既有结构。AI 改写仍需人工核对是否与旋律段落、句长及演唱顺序相符。

#### 5.2.4 第 4、5 步：目标风格与生成设置

目标风格描述想要得到的新编曲和演唱，例如本页初始文本 `Jazz-funk, warm lead vocal, Rhodes piano, electric bass, tight drums`。源曲的实际风格不会自动分析并替换这一栏。

| 乐谱模式 | 适用场景 | 和弦处理 |
|---|---|---|
| 仅旋律（推荐） | 希望主要沿用旋律，让模型重新配和声。 | 建议 ABC 中不带和弦符号。选择此模式不会自动删除手工粘贴或已存在的和弦。 |
| 旋律 + 和弦 | 希望同时提供原和声或自己改过的和弦。 | ABC 应实际含有希望采用的和弦；切换模式不会自动为缺和弦的谱补写和弦。 |

本页不提供“不使用乐谱”。生成数量为 1～16 首，初始种子数值为 `831001`；是否在每次提交前自动更换种子，以随机种子旁的选项为准。ODE、种子、数量、CFG、作品名、高级采样与音频解码参数完整说明见第 4 章。这里使用现有 ABC，调整“乐谱采样”并不会自动重写已经填入的旋律；想重写旋律应修改 ABC 或进入乐谱编辑重新规划。

“仅旋律”模式下，如果生成时检测到 ABC 中仍有和弦，程序会询问是否去掉：

- 选“是”：删除当前乐谱中的和弦符号，并用删除后的 ABC 生成。
- 选“否”：保留当前 ABC，仍按已选的“仅旋律”模式提交。
- 选“取消”：本次不生成。

“仅旋律”复选框和下方模式按钮并非双向同步的同一个开关：上方复选框控制下一次扒谱，并在切换时设置生成模式；手动点击下方模式不会反过来改变上方复选框。扒谱前看上方选项，生成前以下方实际选中模式和 ABC 内容为准。

#### 5.2.5 生成、来源冲突与分析结果复用

点击“生成翻唱”会新建任务并运行到音频完成；`Ctrl+Enter` 在本页同样触发生成。“停止”用于取消当前后台任务。结果区的使用见第 5.3 节。

源音频已换成另一首，而当前乐谱或识别歌词有明确的旧源记录时，点击生成会出现“源歌曲与乐谱/歌词不一致”提示：

| 选项 | 后续动作 |
|---|---|
| 重新扒取旋律 | 对当前源歌曲重新扒谱，暂不生成翻唱。该选项不会顺便重新识别歌词，仍需单独处理旧歌词。 |
| 仍使用现有乐谱和歌词 | 按当前编辑器实际文本生成；不会自动换成新源音频的旋律或歌词。 |
| 取消 | 返回页面检查输入。 |

手工粘贴或导入的谱无法可靠追溯音频来源，应自行确认是否配套。程序记录“原曲路径”也不代表生成器重新读取该录音做声纹或伴奏复制。

可复用其他页面的分析结果：从“扒谱分析”发送到翻唱，会带入源音频、ABC 和段落结构；从“歌词识别”发送到翻唱，会带入当前编辑后的歌词，若该次识别包含有效扒谱结果，也会带入对应乐谱。若只发送歌词并切换了源歌曲，原来的 ABC 可能仍留在翻唱页，需再次检查或扒谱。

翻唱页没有单独的“保存草稿”或“载入草稿”按钮。需要保留手改的 ABC 可用“另存为”；生成启动后会建立保存任务，之后通过作品库恢复。已有翻唱作品可从作品库“编辑乐谱再生成”继续改编。关闭程序前，不要假定本页尚未提交的所有编辑都会像创作页输入一样自动恢复。

### 5.3 生成进度、多版本结果和后续操作

#### 5.3.1 进度与保存提示

完整歌曲流程显示“加载模型 → 规划乐谱 → 生成歌曲 → 声学合成 → 解码音频”。使用现成 ABC 时，规划阶段会显示使用提供的乐谱；继续任务会跳过完整保存的阶段，因此不一定逐项从头显示。

进度区显示当前步骤、补充信息和已用时间。有已知总量时显示当前阶段进度；滚动式进度条表示当前没有可计算的总量，不应当作整个任务精确完成百分比。结束时以文字消息判断完成的是“乐谱草稿”还是“歌曲音频”。

“已保存”提示显示最近保存的阶段。旁边的“在作品库继续”只负责跳到相应任务，不会一点击就开始生成；进入作品库后再点击“继续任务”。音频完成后，该入口会显示“查看作品”。

#### 5.3.2 多版本与结果列表

创作、翻唱、按谱生成都支持同一组输入生成 1～16 个版本，各首依次使用递增种子，并分别保存作品目录。每完成一首就能在结果中选取查看，无需等全部版本完成。

右侧累积两个及以上结果时会显示结果列表；条目包含标题或种子、时长和目录名。选择条目后，播放器、乐谱、生成信息和导出按钮都对应这首作品。开始新任务并不会清空已完成的结果，因此任务运行中仍可能看到上一首的播放器和详情，要以当前选中条目为准。

#### 5.3.3 全部结果操作

| 按钮或页签 | 用途 |
|---|---|
| 音频播放器 | 试听选中的完整歌曲，公共控制见第 2 章。 |
| 打开文件夹 | 在资源管理器中打开/定位该作品的音频文件所在位置。 |
| 导出 MP3 | 将选中音频转成同目录、同主文件名的 `.mp3`，码率采用设置页的 MP3 配置；已有同名 MP3 会覆盖。导出成功后结果面板会定位导出的文件。 |
| 编辑乐谱再生成 | 把所选歌曲的 ABC、风格、歌词和生成参数送入乐谱编辑页。没有 ABC 时不可用。 |
| 导出乐谱 | 打开乐谱与钢琴等导出窗口。只在有 ABC 时可用，具体格式和设置见第 12 章。 |
| 乐谱预览 | 展示所选结果的五线谱与旋律试听，操作见第 7.3 节。乐谱编辑页的结果区不重复放该页签，请使用独立的“实时预览”。 |
| ABC 文本 | 只读查看结果的乐谱文本；没有乐谱时显示直接生成模式无乐谱提示。需要修改时使用“编辑乐谱再生成”。 |
| 生成信息 | 查看输出目录、音频时长、种子、规划模式、ODE、CFG、各阶段耗时、风格和歌词。 |

若“生成信息”提示达到生成长度上限，歌曲或规划可能被截断。可以按第 4 章检查最大 tokens 等参数后创建新任务；仅继续已完成任务或重新解码，不能补写被截断的后半首。

## 6. 批量生成

“🔁 批量生成”把多首歌曲整理为一个可保存、可审核、可继续的批次。左侧填写新批次的输入与参数，右侧选择已建立的批次、查看逐歌进度并处理审核或失败项。

一个批次最多包含 **200 个歌曲条目**。每个条目可以生成 **1～16 个音频版本**。例如，3 个主题、生成数量设为“2 个/首”，就是 3 份歌词、最多 6 个成品版本；“一个主题写多首”设为 5 首、生成数量设为“2 个/首”，则是 5 份歌词、最多 10 个成品版本。多份歌词和同一份歌词的多个音频版本是两层不同设置。

本章的“默认值”指没有恢复旧草稿时的页面初始值。程序会恢复上次保存的输入草稿，实际看到的值可能不同。批次建立后会保存当时的流程与生成参数；**修改左侧参数不会修改已经建立的批次**。继续旧批次前应看右侧的批次摘要，确认选中的是所需批次。大模型 API 使用运行时“设置 → 大模型 API”中的当前配置。

### 6.1 选择批量模式

| 页面顶部选项 | 输入与处理流程 | 使用场景 |
| --- | --- | --- |
| **批量翻唱改词**，默认 | 多首音频 → 按需扒谱 → 识别原歌词 → AI 改词 → 按需 AI 生成风格 → 按需审核 → 生成 | 已有带人声的歌曲，希望按统一要求改写歌词，并选择沿用扒出的旋律、旋律与和弦，或者重新作曲 |
| **批量创作** | 多个主题或歌词文件 → 按需导入 → AI 写词、润色或直接使用 → 按需 AI 生成风格 → 按需审核 → 生成 | 从主题写新歌，或给现有歌词创作音乐 |

每首歌的步骤依次为：**扒谱 → 识别／导入 → 改词／写词 → AI 风格 → 审核 → 生成**，不需要的步骤直接标为“—”跳过（例如不选“AI 生成风格”时没有 AI 风格步骤）。每一步完成后立即保存，停止、出错或程序被关闭后，继续批次只做尚未完成的步骤。

翻唱使用扒出的乐谱作为生成条件，最终歌曲由 YuE2 生成。它不提供“原伴奏保持不变”或“克隆原歌手声纹”的保证；扒谱、歌词识别、改词及音频生成均可能出现偏差，应审核歌词并试听成品。

批次运行时占用全局任务执行器，其他页面不能同时启动常规生成、扒谱等任务。批次表格编辑、切换批次、审核、重试和跳过也需要等任务空闲后进行。

### 6.2 批量翻唱改词：歌曲列表与识别语言

在“歌曲列表”中，可以拖入多个本地文件、拖入文件夹，或使用下方按钮。按完整文件路径去重：同一路径不会重复添加；内容相同但路径不同的文件仍是不同条目。

| 控件 | 如何使用及实际范围 |
| --- | --- |
| **添加文件** | 打开文件选择器，可一次选中多个音频。常用格式为 MP3、WAV、FLAC、M4A、AAC、OGG、OPUS、WMA；也接收 MP4、MKV 中的音频。列表还支持 `.webm`，可拖入、通过文件夹添加，或在文件选择器中切换“所有文件”后选择。扩展名匹配不代表文件一定能成功解码。 |
| **添加文件夹** | 递归查找子文件夹中的支持格式，按路径排序后加入。每次扫描一个文件夹最多收集 5000 个匹配候选；建立批次时仍受 200 首上限约束。只保留本批次需要的文件再开始。 |
| **移除所选** | 在输入列表中选中一项或多项后移除。仅改变新批次的输入列表，不删除磁盘源文件，也不改变右侧已建立批次。 |
| **清空** | 清空当前输入列表。不会删除源文件和已有批次。 |
| 列表编号、数量与悬停提示 | 编号随列表内容重排，右侧显示文件数量；悬停文件条目可查看完整路径。文件名不含扩展名的部分将用作歌曲名称。 |
| **识别语言** | 仅用于识别原音频中的歌词，默认“自动识别”。可选中文、粤语、英语、日语、韩语、法语、德语、西班牙语、俄语、葡萄牙语、意大利语、泰语、越南语、印尼语。所有输入歌曲语言一致时可以统一指定；混合语言列表可先用自动识别，或按语言分别建批次。它与 6.4 的“歌词语言”不同，后者用于要求 AI 输出哪种语言。 |

批次会保存源文件的路径，不会在建立批次时复制整份源音频。尚未完成扒谱或识别时，请保持源文件可访问。识别会启用歌词对齐；已有扒谱段落结构时使用该结构，否则不提供已有段落结构。去除段落标签和空行后，若只识别到不足 **8 个近似演唱单位**的歌词，该首会在识别步骤失败，提示可能是纯音乐或人声太弱。这是输入质量检查，不是对音频是否有人声的可靠鉴定。

### 6.3 批量创作：三种创作来源

#### 6.3.1 每行一个主题

这是切换到“批量创作”后的默认输入方式。每个非空主题行建立一个歌曲条目，格式为：

```text
主题
主题 | 语言
主题 | 语言 | 风格
```

例如：

```text
毕业季的离别
夏天夜晚的海边 | 英文
写给妈妈的歌 | 中文 | warm folk, female vocal, acoustic guitar
```

主题最多 **500 字符**，前后空白会清理；空行以及 `|` 前主题为空的行会被忽略。重复主题行会分别建立条目，不按文字去重。歌曲名称取主题的前 20 个字符，完整主题仍保存在批次中，可在右侧名称单元格上悬停查看。

`|` 后的语言只有在“歌词语言”选择 **每首单独指定** 时生效；风格只有在“风格”选择 **每首单独填写** 时生效。若只想填写风格而不指定语言，应保留中间的空位置：

```text
雨后城市散步 | | mellow jazz, warm male vocal, piano
```

这里的半角 `|` 是分隔符，没有主题内使用 `|` 的转义语法。第三段之后再出现的 `|` 会保留在风格字段中。直接“开始新批次”时，如果行内语言或风格因模式不匹配而不生效，确认框会提醒；不要把写在主题行里的值当作自动覆盖统一设置的指令。

#### 6.3.2 导入歌词文件

每个 `.txt`、`.lrc` 或 `.md` 文件建立一首，名称取文件名去掉扩展名。支持拖入文件或文件夹，以及“添加文件”“添加文件夹”“移除所选”“清空”，操作与 6.2 相同。文件夹也会递归查找并按路径去重。

导入限制与整理规则如下：

- 单个文件最多 **1,000,000 字节**；超过时提示“歌词文件超过 1 MB”。
- 先按 UTF-8（兼容 BOM）读取，失败后尝试 GB18030；仍无法解码时需另存为 UTF-8。建议统一使用 UTF-8。
- 去除 LRC 时间标签，例如 `[00:12.34]`；也会去掉独占一行的常见 LRC 元数据标签，例如 `[ar:…]`、`[ti:…]`、`[al:…]`。LRC 时间不会用于控制生成歌曲的演唱时刻。
- 清理每行首尾空白、压缩过多空行。整理后不能为空，也不能超过 **12000 字符**。
- Markdown 文件按文本读入，不会完整解析 Markdown 排版；应只保留歌曲段落标签和歌词，避免把说明文字、列表符号等当歌词送入模型。

“导入后”有两种选择：

| 选项 | 默认与用途 | 注意事项 |
| --- | --- | --- |
| **AI 润色** | 默认。用“改歌词”提示词，按第 ② 张卡片的“润色要求”修改导入的歌词 | 卡片标题为“润色要求（选择“AI 润色”时必填）”，**必须填写**，否则不能建立批次。可填“修正错别字和语病，补全段落标签，不改变原意”。会显示结构约束和结构重试设置。 |
| **直接使用** | 不为歌词发起大模型请求，使用导入后的文本 | 全局写词要求和歌词语言不会自动改写或翻译文本。仍会执行导入清理和最终歌词整理：符合识别规则的开头歌名行会去除；完全没有独占一行的方括号段落标签时，在整体前添加 `[Verse]`。若选“AI 生成风格”，风格仍会调用大模型；审核时“标记让 AI 重改”也会启用 AI 改词。 |

合适的歌词文件示例：

```text
[Verse]
路灯照着回家的方向
晚风带来熟悉的花香

[Chorus]
愿你每次抬头都能看见光
也有人陪你走过漫长
```

#### 6.3.3 一个主题写多首

在“主题”填一个最多 500 字符的主题，“写几首”范围 **1～50 首**，默认 **5 首**。程序为每份歌词分别调用写词模型，并在要求中写明这是第几份、总共几份，要求视角、意象、叙事及段落安排有所不同；已写好的其他版本前两句会作为避免雷同的参考。

歌曲名称为主题前 20 字符；数量超过 1 时追加 `#1`、`#2` 等。该方式只提出差异化要求，不能保证模型生成的歌词一定不同或质量合格。这里没有逐项语言和风格输入框，若要逐首填写，选择对应的逐首模式后先点“📋 只建批次”，再在右侧表格填写，详见 6.8。

#### 6.3.4 歌词篇幅（按主题写词时）

“每行一个主题”和“一个主题写多首”在创作来源卡片底部有 **歌词篇幅**：约 1 分钟／约 2 分钟／约 3 分钟（默认）／约 4 分钟，对整批每首生效，含义与第 3.5 节写词弹窗相同——每档对应一套段落安排和歌词行数，写进发给模型的【篇幅】。YuE2 的歌曲长度主要由歌词长度决定，实际时长还会随旋律、间奏和语言浮动。“导入歌词文件”没有这个选项，长度由导入的歌词决定；批量翻唱的长度由原歌词决定。篇幅会显示在右侧批次摘要里。

按主题写词使用“写歌词”系统提示词；批量翻唱改词、导入歌词的 AI 润色使用“改歌词”系统提示词；“AI 生成风格”使用“风格描述”系统提示词，三者都在“设置 → 大模型 API”分别修改。

### 6.4 改词／写词要求、语言和结构

#### 6.4.1 要求与快捷按钮

卡片标题随来源变化：“批量翻唱改词”为 **改词要求（必填）**；“导入歌词文件”为 **润色要求（选择“AI 润色”时必填）**；按主题写词为 **写词要求（可选，对每首生效）**。要求最多 **2000 字符**，作用于本批次的每首歌。

- 改词／润色：要求作为【修改要求】和原歌词一起发给模型。可以写明主题方向、措辞、意象、押韵、语言和需要保留的内容，比如“改成积极向上的毕业主题，保留原歌词的主要意象，副歌押韵且容易记住”。若同时启用“保持段落和行数”，要求中就不要再要求增加桥段或减少段落，否则两条要求可能冲突。
- 按主题写词：要求作为【其他要求】发给模型，适合写押韵、视角、情绪等。段落数量和长度请用“歌词篇幅”控制，不要在要求里写与篇幅矛盾的段落安排。

快捷按钮也随来源变化：
- 改词／润色时有“副歌更押韵、更好记”“整体更口语化”“改成粤语”“翻译成英文歌词”“改得更伤感”“改得更积极向上”“加一段 [Bridge] 桥段”“精简到两段主歌两段副歌”“修正错别字和语病，不改变意思”“每行字数更整齐”。**点击会替换整个要求框的当前内容**。
- 按主题写词时有“副歌押韵、好记”“口语化，有画面感”“情绪层层递进”“适合男女对唱”“结尾留有余味”“积极向上”“带一点忧伤”。**点击会追加**到要求框末尾，已有的不会重复。

#### 6.4.2 歌词语言

| 选项 | 实际作用 |
| --- | --- |
| **不指定**，默认 | 不额外发送强制语言要求。翻唱可由改词要求表达语言；创作由主题、要求与模型决定。 |
| **统一指定** | 启用右侧可编辑下拉框，所有歌曲把同一语言作为【歌词语言】发给写词／改词模型。预置中文、粤语、英文、日语、韩语；初始选中中文，也可直接输入其他语言名称。不能为空。 |
| **每首单独指定** | 使用主题行第二段或已建批次右侧“语言”列。逐首值留空表示该首不额外指定语言，不会回退到右侧统一语言下拉框。 |

语言字段保存时会合并多余空白，并保留最多 **40 字符**。它是写词提示，不是歌曲演唱语言正确率的保证；“直接使用”歌词时不会凭这个字段翻译文本。风格标签里的语言描述也不替代这里的歌词语言选择。

#### 6.4.3 结构约束

翻唱模式显示“结构约束”；创作仅在“导入歌词文件 + AI 润色”时显示。纯主题创作没有原歌词可比较，程序会把结构约束设为不限制。翻唱即使选“重新作曲”仍会保留该控件，若想自由改变段落可手动选“不限制”。

| 选项 | 检查内容与适用方式 |
| --- | --- |
| **不限制** | 不比较原歌词与新歌词的段落、行数和每行长度。适合需要明显重写结构的任务。 |
| **保持段落和行数**，默认 | 比较有歌词的段落标签顺序及各段歌词行数，不比较每行字数。适合同结构改写，也比按字数约束更适合跨语言翻译。 |
| **严格：每行字数也一致** | 在段落、行数检查基础上比较每行的近似演唱单位，适合同语言改写时控制长度。界面名称虽写“一致”，实际检查有容差，不是逐字相等。 |
| **结构不符时自动重试** | 默认 **1 次**，范围 **0～3 次**。只有存在原歌词且启用结构约束时才进行结构重试。0 表示只请求一版；1 表示初次请求后最多再改一次。每次把上一次发现的问题带给大模型，最后保留问题数量最少的一版，问题数相同则保留较早版本。 |

检查时忽略空行；只有标签、没有歌词的器乐段落不参与结构比较；`[Verse 1]` 与 `[Verse]` 视为同类，标签大小写也不影响比较。标签应单独占一行。严格模式中，中日韩文字大致按字计，空格分词文字按词计，泰文等不依靠空格分词的文字采用近似估计。某行差值 **大于 `max(2, round(原行单位数 × 25%))`** 才报告长度问题，因此它不检验精确音节数或实际演唱对齐。

结构仍有问题时，该首通常会带 **⚠ 警告**继续流程，不会仅因结构问题强制失败。全自动模式可能直接用这版生成；审核模式可手改后通过。需要认真控制歌词结构时，请启用“写词后暂停审核”，不要把没有警告当作旋律适配质量的保证。

### 6.5 风格：统一、AI 生成或逐首填写

| 选项 | 如何使用 |
| --- | --- |
| **统一风格**，默认 | 下方风格框对所有歌曲生效，**必须填写**。即使只建批次，也不能留空。审核窗口隐藏逐首风格输入。 |
| **AI 生成风格** | 每首在改词／写词完成后，作为独立的“AI 风格”步骤再调用一次大模型（“风格描述”系统提示词），根据全局要求、该首主题、最终歌词片段、可用的语言及扒谱速度／调性／拍号信息生成英文风格标签。歌词和风格分别保存进度：风格失败、被停止或程序中断时，已写好的歌词保留，继续或“重试失败项”时只补做风格，不会重新写词。下方统一风格框可留空；此模式不会把其中的文字当作逐首默认风格或 AI 风格提示，若有要求请写入“改词／写词要求”。审核窗口可修改每首实际生成的风格。 |
| **每首单独填写** | 使用主题行第三段或右侧“风格”列；逐首留空时回退到下方风格框。可先填一个默认风格，再只覆盖少数歌曲；或者将默认框留空，逐首全部填写。先“只建批次”允许暂时缺少逐首风格，但继续运行前必须补齐未跳过且尚未开始生成的歌曲。 |

风格框可直接输入英文逗号分隔的标签，例如 `Mandarin, warm folk, female vocal, acoustic guitar, piano, hopeful, mid-tempo`。展开“风格标签库（流派 / 人声 / 乐器 / 情绪 / 语言，点击即可添加）”，按流派、人声、乐器、情绪、语言、速度选择标签；点击会在现有文字后以逗号追加，已存在的同名标签不会重复追加。标签的完整用法见第 4 章。

全局风格最多 **1000 字符**，超限时字符计数变红，建立批次时会拒绝。右侧逐首风格保存时合并空白并截取最多 1000 字符；审核中提交的风格超过 1000 字符则会提示错误。AI 生成的风格最终也最多保留 1000 字符，实际质量仍需检查。

### 6.6 流程选项

#### 6.6.1 翻唱的“旋律”

| 选项 | 批量处理行为 |
| --- | --- |
| **按原旋律（仅旋律）**，默认 | 对每首音频扒谱，仅使用得到的旋律，并去掉和弦标记；YuE2 按旋律条件生成并重新配和声。 |
| **原旋律 + 和弦** | 扒谱并使用得到的旋律与和弦。使用的是识别结果，可能与原曲存在偏差。 |
| **重新作曲** | 跳过扒谱，但仍识别原歌词并按要求改词。随后按新歌词和风格进行创作，内部使用“旋律 + 和弦”规划，不使用原曲旋律作为条件。 |

批量页不提供逐首手工修订扒谱的编辑器。扒谱未得到任何乐谱时失败；仅得到部分乐谱时可能保留结果并显示警告。扒出的 ABC 超过 **100000 字符**时不能继续用于生成。

#### 6.6.2 创作的“乐谱规划模式”

创作模式显示“乐谱规划模式”，翻唱模式则由上面的“旋律”选项决定。

| 选项 | 作用 |
| --- | --- |
| **旋律 + 和弦**，默认 | 先规划带和弦的 ABC 乐谱，再生成歌曲。 |
| **仅旋律** | 规划旋律，不包含和弦。 |
| **不使用乐谱** | 跳过乐谱规划，直接生成。 |

选项含义与共同参数影响详见第 4 章。这里对整个批次统一设置，不能在表格中逐首切换。

#### 6.6.3 审核、执行顺序和出错策略

| 参数 | 选项与默认值 | 怎样选择 |
| --- | --- | --- |
| **审核** | **全自动**，默认；**写词后暂停审核** | 全自动写好词后直接进入生成。暂停审核会让歌词停在“⏸ 待审核”，通过后才允许生成。 |
| **执行顺序** | **按步骤批量**，默认 | 先处理所有可执行歌曲的同一步，再进入下一步，例如先全部扒谱，再全部识别、改词。可减少模型切换；实际总耗时取决于输入、硬件与错误情况。 |
| **执行顺序** | **逐首完成** | 按列表顺序处理一首的全部步骤，再处理下一首，通常可更早得到第一首可试听结果。 |
| **审核期间** | **等这首审核完再继续**，默认 | 仅当“写词后暂停审核 + 逐首完成”时显示。第一首到待审核时结束本轮运行，先审核它再继续，适合逐首严格把关。 |
| **审核期间** | **先处理后面的歌** | 同样仅在上述组合显示。某首待审核后继续处理后面歌曲的前置步骤；待没有可执行步骤时再暂停。审核按钮在任务空闲后才可用，不是在后台继续运行的同时编辑审核。 |
| **出错时** | **跳过出错的歌**，默认 | 失败步骤保留为“✕ 失败”，其他歌曲继续。之后可“重试失败项”。这与人工“跳过所选”不同：出错条目仍可重试，未被永久标成已跳过。 |
| **出错时** | **停止整批** | 任一歌曲步骤报错后结束本轮批次运行，保留已经完成的步骤。修正原因、重置失败项后继续。 |

“按步骤批量 + 暂停审核”会让可处理的歌词进入待审核，再停止本轮任务。通过部分歌曲后，也可在仍有其他待审核歌曲时继续处理已通过的歌曲；具体下一步仍遵守本批次保存的执行顺序。对“逐首完成 + 等这首审核完再继续”，排在前面的待审核歌曲仍会阻挡后面的歌曲。

部分大模型接口错误会强制停止整批，即使选了“跳过出错的歌”：例如 HTTP 401／402／403／404、缺少大模型配置、缺少所需官方 SDK、无效 API Key 等。因为这类错误通常会影响后续所有歌曲，需要先修正当前 API 设置，再重试失败项。

### 6.7 生成设置与调用次数

第 4 章已逐项介绍渲染质量、种子、CFG、采样和解码。本页共享这些控件；批次会记录一套设置并用于每首歌。主要初始值及批量差异如下：

| 控件 | 本页初始值、范围或特殊行为 |
| --- | --- |
| **渲染质量 (ODE 步数)** | 默认 32，范围 8～64；“快速 16”“标准 32”“精细 48”仅设置步数，不保证生成质量等级。 |
| **随机种子** | 本页初始值 **831001**；允许 0～9223372036854775807。它是第一首的起始种子，且所有歌曲和版本的种子都必须不越界。 |
| **🎲** | 立即为输入框抽一个种子；具体通用行为见第 4 章。之后建批次时仍遵守本页的逐歌分配规则。 |
| **每首随机** | 初始不勾选。勾选后，在**建立批次时**为每首分配一个随机起始种子并保存；继续批次不会重新抽种子。每首内部的多个版本仍使用连续种子。随机抽取不构成不同歌曲绝不碰撞的数学保证。 |
| **生成数量**，后缀“个/首” | 默认 1，范围 **1～16**。是每份最终歌词生成的音频版本数量，不是主题数或不同歌词数量。 |
| **文本引导 CFG → 自定义** | 初始不勾选，由管线按模式取默认值；勾选后的初始数值为 1.20，可设 0.00～20.00，步进 0.05。详见第 4 章。 |
| **音频解码设置** | 默认“自动（默认）”；也可选“分块解码”“完整解码”。分块长度默认 1024 帧、范围 64～8192；上下文长度默认 16 帧、范围 12～256，仅分块模式使用。详见第 4 章。 |
| **高级采样参数** | 展开后可勾“启用自定义采样”，分别设置“乐谱规划”和“歌曲生成”；“恢复默认”用于恢复采样默认值。初始未启用自定义。每个参数的默认值、范围和作用见第 4 章。批量页为整批统一保存，不在表格中逐首调节。 |
| 作品名 | 本页没有手填作品名控件。翻唱自动使用文件名加“ · 改词”；创作使用文件名或主题名称，同主题多首追加序号。 |

不勾“每首随机”时，设起始种子为 `S`，每首版本数为 `K`，从第 1 首开始，第 `i` 首的起始种子为 `S + (i−1)×K`。例如 `S=831001`、`K=2`：第 1 首两个版本使用 831001、831002，第 2 首使用 831003、831004。若最后一个版本越过种子上限，建立批次会被拒绝，需要降低起始种子。

开始确认框中的“大模型约调用”只估算**歌词与风格的请求数**，不包括本地扒谱、识别、YuE2 音乐生成等步骤，也不按每首音频版本数量相乘。设条目数为 `N`：

| 输入与风格组合 | 基础估算 |
| --- | --- |
| 翻唱改词、主题写词或 AI 润色 + 统一／逐首风格 | `N` 次 |
| 翻唱改词、主题写词或 AI 润色 + AI 生成风格 | `2N` 次 |
| 导入歌词“直接使用” + 统一／逐首风格 | `0` 次 |
| 导入歌词“直接使用” + AI 生成风格 | `N` 次 |

结构重试、手动重改、交互式 AI 修改以及网络重试会增加次数。每次普通批量大模型请求遇到 HTTP 429、HTTP 5xx、无法连接或提前结束等可重试错误时，最多额外重试 **2 次**，约等待 3 秒、6 秒后重试，可在等待期间停止。估算不是费用承诺，实际计费由所配置的服务商与模型决定。

### 6.8 建立批次、逐歌编辑和继续

#### 6.8.1 “▶ 开始新批次”与“📋 只建批次”

**开始新批次**会校验输入，检查需要调用的大模型是否已配置，然后显示确认框：批次歌曲数、每首版本数、总版本数、估算大模型调用数、执行顺序、审核方式和出错策略。确认后创建批次并开始运行。已有批次仍保留；再次点击该按钮会建立另一个新批次。

**只建批次**只创建并保存批次状态，不运行扒谱、导入、写词或音频生成，也不要求大模型现在就配置好。它仍校验必须填写的全局要求、统一风格、主题和输入文件等；“每首单独填写”模式可以暂时缺少逐首风格。适合先建立条目，再在右侧逐首填语言与风格。

两种操作都最多接受 200 首。输入文件在建立时仅检查路径等基本条件；歌词文件内容与模型执行错误可能到实际运行相应步骤才出现。

#### 6.8.2 右侧表格可以编辑什么

右侧表格列为“#”“名称”“扒谱”“识别／导入”“改词／写词”“AI 风格”“审核”“生成”“语言”“风格”；会按模式隐藏不适用列，例如主题创作不显示导入，重新作曲不显示扒谱，不是“AI 生成风格”时不显示 AI 风格，全自动不显示审核。“AI 风格”是步骤状态列（不能编辑），风格生成失败时在这一列显示“✕ 失败”，悬停可看原因；最后的“风格”列才是逐首填写风格的输入列。

“语言”列仅在所选批次使用“每首单独指定”时显示，“风格”列仅在所选批次使用“每首单独填写”时显示。任务空闲时，激活对应单元格输入；按 Enter 或离开编辑器提交后，程序会保存。编号、名称、状态列不能修改。

| 字段 | 可编辑时机 | 保存规则 |
| --- | --- | --- |
| **语言** | 尚未写好词，且歌曲没有被人工跳过 | 合并多余空白，最多保留 40 字符。已写好词后不能直接改；若该首仍处于审核阶段，可先“标记让 AI 重改”，让写词回到待处理，再在表格修改语言后继续。 |
| **风格** | 尚未建立该首生成任务，且歌曲没有被人工跳过 | 合并多余空白，最多保留 1000 字符。已经开始生成、已有生成任务目录时不能修改，哪怕音频生成尚未完成。需要新风格时，可把歌词复制到单首页面另行生成。 |

表格不是整批参数编辑器。若需要改变旧批次的识别语言、旋律模式、统一要求、每首数量、ODE 等设置，应按新设置重新建立批次；仅修改左侧再点继续，旧批次仍使用已保存的值。

#### 6.8.3 “⏯ 继续所选批次”

先在右侧“批次”下拉框选中目标，核对摘要，再点击“继续所选批次”。程序先提交当前表格编辑，全部保存成功后才启动；根据保存进度执行尚未完成且前置条件满足的步骤。已经完成的批次步骤不会因为继续操作而全部重做。

停止或异常退出时尚在进行的步骤会按未完成恢复，可能需要重做该步骤。音乐生成一旦建立任务，会先记录任务目录，后续继续尝试恢复同一任务中的已保存阶段。某首如果仍标记失败，通常应先点“重试失败项”；如果只剩待审核，则先审核。按钮变灰也可能是其他任务正在运行、没有选中有效批次，或当前没有可执行步骤。

### 6.9 歌词审核窗口：查看、手改与各个按钮

需要审核的批次运行至暂停后，会提示“歌词已写好，请审核后继续”；如果当前选中的就是该批次，通常自动打开“📝 审核歌词”。也可在任务空闲时点击右侧 **📝 审核歌词（数量）**。

窗口左侧只列出当前待审核歌曲，有结构或整理警告时显示 ⚠。中间“原歌词 / 主题（只读）”显示识别／导入的原歌词；没有原歌词时显示主题及可用的语言信息。右侧“最终歌词（可直接修改）”可手工改字、补段落、调整行数。下方即时显示最多 4 条结构问题。

仅在“AI 生成风格”或“每首单独填写”模式显示“风格”输入。统一风格不能在这里逐首覆盖；AI 风格不能为空，逐首填写模式可留空以使用批次默认风格。最终歌词通过时必须非空且最多 12000 字符。

| 按钮或输入 | 操作结果 |
| --- | --- |
| **✓ 通过这首** | 保存当前最终歌词和可编辑风格，重新记录结构警告，将该首审核标为通过，再载入剩余待审核项。有结构警告也可以通过；通过并不自动保证歌词与旋律适配。 |
| **✓ 全部通过** | 确认数量后，逐首保存并通过当前所有待审核项。已在本窗口修改过的歌词／风格会使用窗口草稿，其余使用磁盘上现有版本。逐首提交过程中若某项失败，会停在该项；前面已成功通过的不会撤回。 |
| **✨ 交互式 AI 修改** | 打开“✨ AI 改歌词”，以当前右侧最终歌词为修改基础。应用结果后回到审核窗口，仍需“通过这首”或“全部通过”才正式保存并通过审核。详见 6.10。 |
| **修改意见／补充要求** | 只供“标记让 AI 重改”使用，输入框的提示文字会按歌曲类型说明用法。可留空；提交时合并空白并最多保留 500 字符。**每次打开审核窗口时输入框都是空的**，不会自动填入上一轮已经执行过的意见，所以不会把同一条意见重复叠加到已改过的歌词上；想沿用上一轮的意见需要重新输入。在同一个审核窗口内切换歌曲时，尚未提交的意见和歌词／风格一样按歌曲暂存；关闭窗口后不保留。 |
| **↻ 标记让 AI 重改** | 提交输入的意见，将该首改词／写词、AI 风格（选了“AI 生成风格”时）与审核步骤改回待处理；不会立即请求模型，需继续批次后重做，风格会按新歌词重新生成。**有原歌词的歌**（翻唱、导入歌词）：意见作为“补充要求”和批次要求一起，基于原歌词重新改写。**按主题写的歌**：填写了意见时，用“改歌词”提示词按意见修改 AI 上次写好的那一版（例如“副歌短一点”只改副歌）；留空时按主题重新写一版。两种情况都不会把当前尚未通过的手改歌词作为基础；想基于手改稿迭代，应使用“交互式 AI 修改”。 |
| **跳过这首** | 确认后把该首人工标记为跳过，不再继续生成；已有完成步骤仍保留。 |
| **关闭** | 关闭审核窗口，不会自动通过尚未通过的歌曲，也不会把未提交的手改歌词／风格作为正式结果保存。若本次已通过、重改或跳过且还有可运行步骤，关闭后会询问是否现在继续批次。 |

在同一个审核窗口内切换歌曲时，尚未通过的歌词、风格和尚未提交的修改意见会暂存到这个窗口的内存草稿，再切回来仍可看到；**关闭窗口后这些未提交草稿不会保留**。需要保存修改，请先通过该首。不要把“关闭”当成保存按钮。

“标记让 AI 重改”只接受还没开始生成的歌曲。导入歌词选择“直接使用”时，如果点重改但没填补充要求，程序会自动改用“润色歌词：修正错别字和语病，补全段落标签，不改变原意”，因此下一轮会调用大模型。AI 风格模式下，重做写词后会接着按新歌词重新生成风格。

### 6.10 审核中的“✨ AI 改歌词”详细操作

这个子窗口适合边看结果边修改单首歌词。上方显示当前配置的模型；左侧“当前歌词”只读，右侧“AI 修改结果（可以直接再手动修改）”接收流式结果；生成进行中为只读，结束后才允许手工调整。结果的整理和空内容判断与第 3.4 节相同。

| 控件 | 如何使用 |
| --- | --- |
| **告诉 AI 怎么改／要求输入框** | 填写本轮修改要求。不能为空；按 Enter 与点“✨ 生成”相同。输入框可从历史要求中补全；快捷按钮同 6.4，点击替换当前要求。 |
| **结构** | 可选“不限制结构”“保持段落和行数”“保持段落、行数和每行字数（翻唱贴合原曲旋律）”。初始继承批次结构模式，对本轮传给 AI 的要求生效；参照的是进入子窗口时的当前歌词，或“在结果上继续改”后的上一轮结果。此子窗口没有批量引擎的结构不符自动重试循环。 |
| **附带歌曲风格描述** | 有风格时默认勾选并可切换；没有风格时不可用。勾选会把风格一起提供给修改模型。它不会替你修改审核窗口的风格字段。 |
| **✨ 生成** | 请求一次歌词修改并流式显示。每次生成会清空右侧上轮结果；重复请求会增加实际调用次数。请求期间要求输入与生成按钮暂时禁用。 |
| **■ 停止** | 请求取消当前歌词 API 调用。已收到的部分会去掉思考过程、歌名行等后保留；整理后仍有歌词行时才启用应用和继续修改按钮。部分结果可能不完整，请先检查。 |
| **↪ 在结果上继续改** | 把右侧结果变成左侧新的当前歌词，清空右侧结果和要求输入。再写下一轮要求、点生成，即可逐轮修订；这个按钮本身不发起 API 调用。 |
| **✅ 应用到歌词** | 把右侧文本带回上一级审核窗口并关闭子窗口。右侧为空或只有段落标签时提示“歌词是空的”，不会清掉审核窗口里的歌词。还需在审核窗口点击通过，才能保存为批次最终歌词。 |
| **取消** | 取消本次交互并请求停止进行中的调用，不把子窗口结果应用回审核窗口。 |

完成提示会报告歌词行数变化；回到批量审核窗口后，结构检查仍会针对批次保存的原歌词执行。子窗口里临时更改“结构”选项不会修改整批已保存的结构模式。

### 6.11 查看进度、打开结果、停止、重试与跳过

#### 6.11.1 批次选择和状态

右侧“批次”下拉框显示批次文件夹名、状态和条目数。**🔄** 刷新列表；**📂** 打开当前批次文件夹。列表来自当前输出目录下的 `batch` 子目录，不是导入任意批次路径的入口。无法识别或读取的批次可能不在列表中（旧版程序建立的批次格式不同，也不会列出，需要用当前版本重新建立）；选中批次后读取失败时，摘要会显示“⚠ 无法读取批次”。

摘要显示批次类型、共几首、完成／待审核／失败／跳过数量，以及要求、执行顺序、旋律或规划模式、审核方式、每首版本数、风格和语言策略。进度区按“[当前序号/总数 歌曲名 · 步骤]”报告当前工作；文字接收计数属于大模型流式输出进度，并不是音频生成百分比。

| 表格标记 | 含义 |
| --- | --- |
| **·** | 该步骤待处理 |
| **● 进行中** | 当前步骤正在运行 |
| **✓** | 该步骤已完成 |
| **✕ 失败** | 步骤发生错误；把鼠标放在该单元格上查看错误说明 |
| **—** | 该步骤不适用或已跳过，不一定代表整首被人工跳过 |
| **⏸ 待审核** | 等待用户审核歌词 |
| **⚠**，附加于上述标记 | 有整理、结构或部分扒谱警告；悬停查看文字，不等同于失败 |

| 批次状态 | 怎样处理 |
| --- | --- |
| **待继续** | 批次已建立或仍有待处理步骤，可继续 |
| **运行中** | 正在执行 |
| **等待审核** | 有待审核歌曲，完成审核后继续；可能同时有已通过且可生成的歌曲 |
| **已停止** | 用户停止了本轮运行，已保存的步骤可继续 |
| **已中断，可继续** | 记录里曾在运行，但当前没有运行占用，常见于异常退出；可尝试继续恢复 |
| **出错停止** | 整批因错误停止，查看摘要上次错误和失败单元格 |
| **完成（部分失败）** | 当前没有可继续的正常步骤，但有失败项；可重试或人工跳过 |
| **全部完成** | 所有条目都已经完成或被人工跳过。若包含跳过项，并不表示每个输入都有成品，应同时核对“完成”和“跳过”数量 |

#### 6.11.2 打开所选作品

单击选中一行，再点 **🎵 打开所选作品**；双击行也会执行打开操作。若已有成品结果，定位到作品库中的第一个结果；否则若生成任务目录存在，定位到该任务。还没有生成任务时，打开该首在批次中的中间文件夹。

一首有多个版本时，这个按钮首先打开第一份，不是一次展开播放所有版本。后续试听、导出、删除作品等操作见作品库章节。批次文件夹中的 `batch.json` 保存设置、状态和生成任务关联；`items` 下按歌曲保存原歌词、最终歌词、可用乐谱与 AI 风格等中间产物。恢复依赖这些文件及尚需读取的源文件，不宜在运行中移动或手工修改。

#### 6.11.3 “■ 停止”

点击底部 **■ 停止** 请求取消正在运行的全局任务。停止依赖当前步骤响应取消，可能需要等待；已有完整步骤保留，当前未完成步骤下次可能重做。停止不会删除批次，也不是人工跳过某首歌。

若关闭主窗口时任务仍在运行，程序会询问是否退出。为便于确认保存进度，通常先点停止并等本轮结束，再关闭。再次启动后从右侧选择已有批次继续，避免误点“开始新批次”重复建立任务。

#### 6.11.4 “↻ 重试失败项”

此按钮在任务空闲且有失败歌曲时可用，处理的是**当前所选批次内所有失败步骤**，不是仅重试表格选中行。它把失败步骤重置为待处理，不重新标记已完成步骤。

若存在已有生成任务的失败项，会出现三个按钮：

| 按钮 | 使用情形 |
| --- | --- |
| **继续原任务** | 通常先选它。已完成的乐谱、tokens 等已保存生成阶段不重做，恢复原任务。 |
| **新建任务重新生成** | 原生成任务被删除、损坏，或提示“推理版本不同”而不能恢复时使用。解除批次对旧生成任务／结果的关联，下一次生成建立新任务；仍使用本批次保存的歌词、风格和生成参数。旧任务如果仍在，仍保留在作品库，不会因此自动删除。 |
| **取消** | 保持失败状态，不重置 |

重置后会提示“已重置 N 个失败步骤，现在继续批次吗？”这里的 N 是步骤数，不是成品数。选择继续立即运行；暂不继续则保留重置状态，以后可点“继续所选批次”。先处理报错原因再重试，避免重复消耗时间和 API 调用。

#### 6.11.5 “⏭ 跳过所选”

空闲时选中未完成歌曲，点 **⏭ 跳过所选** 并确认。该首会人工标记为已跳过，未完成步骤变为“—”，其他歌曲可以继续。当前界面没有“撤销人工跳过”按钮；“重试失败项”不会恢复人工跳过条目。

已完成或已跳过的歌不能再次跳过。若某首已经开始生成且生成步骤没有失败，也不能通过此按钮跳过；可处理或继续原生成任务，生成结果的删除到作品库完成。生成步骤已经失败时，仍可选择人工跳过。

### 6.12 保存失败与常见错误的处理

#### 6.12.1 表格语言／风格保存失败：当前版本的具体行为

表格文字提交后会排队保存，保存目标绑定当时的批次与歌曲编号；切换批次不会把输入误写到另一个同编号歌曲。创建批次、继续、刷新、切换批次、审核、重试、跳过及关闭前，会先结束当前单元格编辑并尝试保存。保存失败时不会按旧值直接启动本次操作。

| 保存问题 | 程序如何处理 | 用户下一步 |
| --- | --- | --- |
| 占用或可恢复读写异常，即 **RuntimeError、OSError**，包括权限、文件共享冲突、磁盘空间等问题 | 保留未保存输入，提示“未保存的编辑已保留”。自动刷新不会用旧数据覆盖它；切换批次会退回原批次。本次继续等操作中止。 | 解决文件占用、目录权限、磁盘空间等原因后，点击“继续”、刷新，或再次关闭窗口重试保存。仍失败时先把重要文字另行复制保存。 |
| 目标不存在或不再接受编辑，即 **FileNotFoundError、ValueError、KeyError** | 提示“以下表格编辑无法保存，已放弃”，移除这些待保存编辑；**本次触发操作仍会中止**。`FileNotFoundError` 虽属于 `OSError` 的子类，在这里按不可保存情形优先处理。 | 阅读提示并检查批次／歌曲是否存在、记录是否合法、是否已写好词或开始生成。需要的话重新输入允许编辑的字段；确认后再点击一次操作。不要误以为刚才文字已保存。 |

关闭主窗口时，程序会再次尝试保存。若仍有保留的未保存编辑，会问：“批量生成表格里有编辑还没保存。放弃这些编辑并退出吗？”默认是 **否**：留在程序里等待稍后保存。选择 **是**才会放弃这些表格编辑并退出。不可恢复类型已明确提示放弃的编辑不会再次作为待保存内容拦住退出。

以上分类专指批量表格逐首语言／风格编辑，不能推广成“所有文件保存失败都有自动保留”。审核窗口提交失败会显示错误并保留当前窗口以便检查，但仍应在关闭前确认所需内容已通过并成功保存。

#### 6.12.2 常见报错

| 提示或现象 | 检查与处理 |
| --- | --- |
| “请填写改词要求”／“AI 润色需要填写写词要求” | 补齐要求；主题创作才可不写要求。 |
| “统一风格需要填写风格描述”／提示逐首风格缺失 | 统一模式填全局风格；逐首模式填默认值或每首风格。“只建批次”后遗漏的逐首风格必须在继续前补全。 |
| 歌词文件空、超 1 MB、超过 12000 字符、编码无法识别 | 整理源文件并另存为 UTF-8，保留必要歌词与段落标签。待导入步骤重试时仍会读取原路径。 |
| 识别歌词太少、可能是纯音乐或人声太弱 | 核实源音频确有清晰人声和足够歌词。若需要换“识别语言”，应在左侧改好后建立新批次；旧批次继续使用保存的识别语言。无法识别的条目可跳过。 |
| 扒谱没有得到乐谱／只有部分乐谱 | 查看失败或警告。部分乐谱可能仍用于后续生成；需要改用“重新作曲”时，以新旋律选项另建批次。 |
| “模型返回了空内容”／“模型没有返回歌词正文”／AI 风格为空 | 批量 AI 写词／改词只返回歌名、只有段落标签或没有正文时，该首的改词／写词步骤记为失败，不会带着空歌词去生成歌曲。检查 API 状态、所选模型与修改要求，修正后“重试失败项”；风格失败只需重试风格，歌词不会重写。审核中也可手填允许编辑的风格。 |
| API 配置错误或无效 Key，批次整批停止 | 在“设置 → 大模型 API”修正当前配置，再回批次点“重试失败项”。已写好词且剩余步骤不需要大模型时，恢复不会仅因缺少 API 配置重新写词。 |
| 显存不足／`out of memory` | 查看错误详情及第 4 章显存相关参数。程序检测到该错误后会尝试卸载模型释放资源；再按错误策略继续或停止。若需要改解码／采样等已保存生成参数，应在单首页面按新参数建立任务，或另建新批次；不能只改左侧再继续旧批次，“新建任务重新生成”也仍使用本批次保存的参数。 |
| “推理版本不同”、原生成任务损坏或不存在 | 在“重试失败项”中选择“新建任务重新生成”，前提是批次的最终歌词、风格等仍完整可用。 |
| “这首歌已经开始生成，不能再改词／修改风格不会生效” | 该首生成参数已经进入生成任务。把所需歌词与风格复制到单首创作／翻唱页另行生成，或按新输入建立批次。 |
| “继续所选批次”灰色 | 等当前任务完成；检查所选批次是否有效；待审核先审核，失败先重试。全部完成或全部人工跳过时没有后续步骤可继续。 |

### 6.13 操作示例一：三首音频改成励志歌词，逐首审核

1. 打开“🔁 批量生成”，保持“批量翻唱改词”。用“添加文件”加入 3 首清晰带人声的音频，确认输入列表为 3 个。
2. 若三首均为普通话，识别语言选“中文”。在“改词要求”填：“改成积极向上的励志歌词，保留原歌主要意象和叙事顺序，副歌押韵好记”。
3. 歌词语言选“统一指定”，语言填“中文”。结构选“保持段落和行数”，结构不符自动重试设 1 次。若准备严格同语种逐行控制，可改选严格模式，并在审核时检查结果。
4. 风格选“统一风格”，填 `Mandarin, uplifting pop, bright female vocal, piano, acoustic guitar, hopeful, mid-tempo`。
5. 旋律选“按原旋律（仅旋律）”；审核选“写词后暂停审核”；执行顺序选“逐首完成”；审核期间选“等这首审核完再继续”；出错时选“跳过出错的歌”。
6. 生成数量设“2 个/首”，种子用 831001，不勾“每首随机”；ODE 保持 32，其余共同参数先保持默认。预计 3 份改写歌词、最多 6 个音频版本，基础歌词大模型调用约 3 次，重试会增加。
7. 点“▶ 开始新批次”，核对确认框后开始。第一首写好词时暂停审核。核对原歌词与最终歌词，必要时手改或“交互式 AI 修改”；检查后点“✓ 通过这首”。
8. 关闭审核窗口，在“现在继续批次吗？”中选择继续。第一首进入生成，随后处理第二首；按同样方式审核各首。需要暂离时点“■ 停止”，以后选择这个批次并继续。
9. 选中完成行，点“🎵 打开所选作品”试听，去作品库检查两个版本。若某首失败，悬停失败格看原因，解决后点“↻ 重试失败项”；决定放弃该输入时才用“⏭ 跳过所选”。

### 6.14 操作示例二：三个主题、不同语言和风格，先建批次再填写

1. 切换“批量创作”，保持“每行一个主题”，输入：

   ```text
   毕业季的离别 | 中文 | nostalgic pop, female vocal, piano, mid-tempo
   夏天夜晚的海边 | 英文 | mellow indie pop, male vocal, acoustic guitar
   写给妈妈的歌 | 中文 |
   ```

2. 写词要求填：“每首两段主歌两段副歌，语言自然，副歌押韵好记，避免解释性文字”。歌词语言选“每首单独指定”，风格选“每首单独填写”，下方默认风格暂时留空。
3. 乐谱规划模式选“旋律 + 和弦”，审核选“写词后暂停审核”，执行顺序选“按步骤批量”，出错时选“跳过出错的歌”。生成数量设“1 个/首”；可以勾“每首随机”，其余参数保持默认。
4. 点“📋 只建批次”。右侧出现 3 行，前两首语言和风格已来自主题行。第三首“风格”填 `Mandarin, warm folk, gentle female vocal, acoustic guitar, grateful, slow tempo`，按 Enter 提交；确认没有未保存提示。
5. 核对右侧摘要，点“⏯ 继续所选批次”。程序逐首写词，基础约调用大模型 3 次；完成可处理歌曲的写词后进入待审核。主题创作没有原歌词结构可比较，不使用原歌词结构约束。
6. 在审核窗口逐首核对语言、内容与风格。“✓ 通过这首”适合逐首保存；全部核对完后也可点“✓ 全部通过”。若第二首英文不满意，选中它填补充要求并“标记让 AI 重改”，关闭后继续，让该首再写一版并重新审核。
7. 通过后继续批次，完成后在右侧逐行打开作品试听。随机种子已在建批次时记录，停止后继续不会重新随机。

如果希望同一主题写 5 首，把步骤 1 换成“一个主题写多首”，填主题并设“写几首”为 5；如果希望同一份现成歌词各生成两个版本，改用“导入歌词文件”，根据需要选“AI 润色”或“直接使用”，再将“生成数量”设为“2 个/首”。不要通过增加音频版本数来期待自动得到不同歌词。

## 7. 乐谱编辑

### 7.1 进入编辑页与工作区

“乐谱编辑”用于修改 ABC 中的旋律、和弦与段落，再用当前风格和歌词重新生成歌曲。它是文本乐谱编辑器，五线谱窗口用于查看和试听；界面没有钢琴卷帘或在五线谱上拖动音符的编辑工具。

可以通过以下入口载入：创作页“仅生成乐谱草稿”、生成结果或作品库“编辑乐谱再生成”、本页“载入作品文件夹”，以及 ABC 编辑器“打开”。从“扒谱分析”发送乐谱到这里，也可继续改谱。

| 区域或页签 | 内容与用途 |
|---|---|
| 乐谱 ABC | 显示来源目录、ABC 文本和乐谱工具栏；主要编辑位置。 |
| 风格与歌词 | 调整编曲描述与歌词。修改歌词时尽量让段落与谱中 `% verse` 等注释对应。公共输入工具见第 4 章。 |
| 生成设置 | 设置模式、ODE、种子、数量、CFG、作品名、解码和高级采样；这里也有“继续已保存任务”。 |
| 实时预览 | 查看当前输入 ABC；文本停止变动约半秒后刷新。 |
| 生成结果 | 查看按谱生成的音频、只读 ABC 和生成信息，结果操作见第 5.3 节。 |

从另一份作品载入时，会替换本页的乐谱、风格、歌词和参数。从扒谱分析只发送乐谱时，会保留本页已经填写的风格与歌词，便于接着创作；生成设置仍会根据传入信息载入。使用任何载入入口前，先保存仍需保留的编辑。

本页只允许“旋律 + 和弦”与“仅旋律”，没有“不使用乐谱”。导入作品记录的模式不属于这两项时，页面会采用“旋律 + 和弦”。

### 7.2 ABC 编辑器的全部按钮与统计

| 控件 | 操作 | 边界 |
|---|---|---|
| 打开 | 选择 `.abc`、`.txt` 或其他文本文件，替换当前 ABC。 | 按 UTF-8 读取；有无法解码的内容可能显示替换字符。它只打开乐谱，不会自动载入同目录的歌词、风格和旧任务。 |
| 另存为 | 选择路径，按 UTF-8 保存当前文本为 `.abc`。 | 只保存可读乐谱文本，不等于完整草稿，不保存当前风格、歌词和生成参数。 |
| 去掉和弦 | 移除谱行中类似 `"C"`、`"Am7"`、`"N.C."` 的和弦标记。 | 保留旋律文本；不会删除所有声部或所有同时发声的音符，也不是重新配和声。标准头部行与 `%` 注释行中的文字保留。建议先“另存为”保留原谱，不要依赖此按钮可撤销。 |
| 文本编辑区 | 粘贴或编辑 ABC，可使用常见文本选择、复制、粘贴等操作。 | 修改后更新实时预览；语法高亮只是辅助阅读，不等于生成前已完成严格音乐检查。 |
| 行数、约小节、和弦符号统计 | 快速查看文本规模与和弦数量。 | 小节数是按谱行中的竖线符号估算，反复线等可能使统计与实际演奏小节数不同。 |

普通手动编辑可使用文本框的撤销功能。打开文件、载入作品和“去掉和弦”等整体替换操作可能重置编辑历史，保留版本应依靠“另存为”或“保存草稿”。

页面没有独立的“乐谱示例”按钮。下面是可自行粘贴的简短 ABC 练习，仅用于理解编辑与预览，不是完整歌曲模板：

```abc
X:1
T:旋律练习
M:4/4
L:1/4
Q:1/4=90
K:C
% verse
"C" C D E G | "F" A G F E | "G" D E G B | "C" c4 |]
```

这段示例设定 4/4 拍、四分音符为默认时值、四分音符每分钟 90 拍、C 大调。双引号中的内容是和弦标记，`|` 为小节线，末尾 `c4` 表示上方 C 音持续四个默认时值。可以先改一个音符或一个和弦，再对照实时预览和试听检查变化；真正生成时还需填写相匹配的风格与歌词。

### 7.3 实时预览与旋律试听

预览把 ABC 渲染为五线谱，显示能识别的乐谱警告；无法渲染时提示失败。修改 ABC 后会重新生成预览，并停止旧谱的试听。

内嵌播放器提供播放/暂停、从头重播、循环、进度定位与速度调整。这里试听的是谱面合成出的旋律及可能的和弦伴奏，用来校对音高、节奏和谱面结构，不是 YuE2 最终演唱成品。试听速度调整不会写回 ABC，也不会直接修改下一次生成歌曲的参数；需要修改谱面的速度时应编辑 ABC 中相应内容。

乐谱试听需要联网加载音色。若显示“试听不可用”，仍可以编辑和保存 ABC；若没有成功加载 QtWebEngine，五线谱预览整体不可用，但 ABC 文本仍可编辑。需要导出文件时使用本页“导出乐谱”，格式、渲染条件及离线音色设置见第 12 章。

### 7.4 本页全部操作与三种生成选择

| 按钮 | 使用场景 | 使用哪些输入 | 保存方式 |
|---|---|---|---|
| 载入作品文件夹 | 打开已保存草稿、规划或作品。 | 从所选目录读取乐谱和参数，并检查保存文件。 | 只载入，不运行生成。 |
| 保存草稿 | 保存当前编辑，或另存一份规划副本。 | 当前页面的整套输入。 | 总是创建新草稿，原作品不覆盖；保存成功后页面来源切换到新草稿。 |
| 导出乐谱 | 导出当前 ABC 的 PDF／PNG／SVG；如需钢琴 WAV，必须另有 MIDI。此窗口不从 ABC 生成 MIDI。 | 当前编辑器中的 ABC。 | 打开第 12 章所述导出窗口。 |
| 重新规划乐谱 | 希望模型按当前风格、歌词、种子重新写谱。 | 当前文字与参数；忽略当前 ABC 内容。 | 创建新的规划任务，每次一份；不会生成音频。 |
| 按此乐谱生成 | 使用自己当前编辑的乐谱创作新版本。 | 当前 ABC、风格、歌词及生成参数。 | 新建任务；按生成数量生成 1～16 首，原作品不覆盖。 |
| 继续已保存任务 | 沿用载入时的完整规划和原参数。 | 旧任务保存的输入，不采用后来修改的内容。 | 在该任务目录内接续尚未完成的阶段。 |
| 停止 | 取消当前后台任务。 | 当前正在运行的任务。 | 保留已经完整保存的阶段。 |

“按此乐谱生成”要求 ABC 非空、风格非空且不超过 1,000 字符、歌词非空且不超过 12,000 字符。`Ctrl+Enter` 在此页触发该按钮。“仅旋律”模式下，本页不会像翻唱页一样弹出去和弦确认；要去掉现有和弦，请先用 ABC 工具栏操作。

“重新规划乐谱”在已有 ABC 时会先询问是否覆盖编辑器。点击同意后，新规划使用当前风格、歌词、种子和乐谱采样重新生成，不把原来的 ABC 当作续写对象。完成时如果当前作品或输入已经发生变化，新规划会保存到作品库但不覆盖编辑器；否则自动载入新规划并显示实时预览。

### 7.5 保存草稿、复制规划与继续旧任务的区别

未修改载入的整套参数，并且来源包含完整可校验的规划时，“保存草稿”会创建保留原规划的新草稿副本；它保留可用于续跑的完整规划，而不仅仅是屏幕上的 ABC。不会复制原音频及之后所有已生成阶段。

如果已经修改乐谱、歌词、风格或参数，或者来源只有外部 ABC，“保存草稿”会把当前输入另存为新的输入草稿。此时没有可直接复用的原生规划，后续从新草稿的起点处理。只另存一个 `.abc` 文件也不具备完整规划续跑能力。

“继续已保存任务”只在载入了可继续的歌曲任务时可用；单独的 `.abc`、没有新任务记录的旧作品、已经全部完成的单首任务，以及无乐谱模式的任务，不能在这里继续。无乐谱任务若可恢复，请到作品库操作。

按钮可点击后，如果又修改了输入，程序仍会在实际提交前检查并拒绝续跑，提示使用“按此乐谱生成”创建新任务，或重新载入原任务后继续。修改参数不会被悄悄用于已经保存的旧阶段。

典型选择是：只想把已规划好的原曲做完，用“继续已保存任务”；改了音符、和弦、歌词或风格，用“按此乐谱生成”；希望换一套旋律构思，用“重新规划乐谱”。

## 8. 扒谱分析

“📝 扒谱分析 · SheetSage2”把歌曲录音分析为人声旋律、器乐旋律、和弦、节拍、调性和段落结构，生成可继续编辑的 ABC 乐谱、MIDI 和时间标注。适合先研究原曲、为 AI 翻唱准备旋律，或把分析结果送进乐谱编辑。它识别的是这些音乐要素，不能据此期待每一种乐器都被还原成独立的完整演奏声部。

本章的默认值指页面代码初始值。设备、模型位置和输出根目录按“设置”中的配置执行；这里不需要填写模型路径。

### 8.1 从音频开始

1. 在“音频”区域拖入一首本地歌曲，或点击“拖入歌曲音频，或点击选择”选取文件。
2. 用下方播放器确认选中的是目标歌曲，检查人声、伴奏及开头是否正常。扒谱处理的是所选文件；播放器的播放位置不是分析起点。
3. 若准备做 AI 翻唱，勾选“仅旋律乐谱”；若要查看带和弦的乐谱，则保持不勾选。
4. 首次尝试可以将“只分析前”设为 30–60 秒，保留“默认”预设及窗口参数，点击“🎼 开始扒谱”。正式分析整首时把时长限制恢复为 0。
5. 完成后先看“诊断信息”，再检查乐谱、和弦和段落。需要修订时点击“🎼 在乐谱编辑中打开”；需要生成翻唱时点击“🎙️ 发送到 AI 翻唱”。

“停止”用于请求取消当前任务。任务运行期间若更换源音频，页面会清空旧概览与分析视图；旧任务若随后完成，结果仍保存在其输出目录，但不会填入新音频的页面。

### 8.2 识别选项逐项说明

| 中文界面名称 | 选项、范围与默认值 | 生效条件、用途与调整影响 |
|---|---|---|
| 仅旋律乐谱（ABC 与伴奏 MIDI 中去掉和弦，用于 YuE2 翻唱） | 开／关；默认关 | 开启后，ABC 与播放用 MIDI 去掉和弦伴奏，保留人声和器乐旋律。适合把旋律作为翻唱条件。模型仍分析和弦，原始事件及和弦 LAB 标注仍保留；这也不是人声分离开关。 |
| 预设 | “默认”／“论文参数（兼容读取）”；默认“默认” | “默认”采用重叠窗口拼接，使用下方手动窗口参数。“论文参数（兼容读取）”固定 overlap=100 秒、lookahead=0 秒，采用兼容的音频读取方式，供比对该预设行为。它不保证与论文环境逐位一致，也不是一键提高准确率。 |
| 计算精度 | “BF16 快速”／“FP32 精确”；默认 BF16 | BF16 在 CUDA 上启用混合精度，通常更适合控制推理开销。FP32 关闭这一路混合精度，适合做数值对照，可能更慢、占用更多资源。CPU 实际走 FP32。界面的“精确”表示数值精度，不保证识别一定更准确。 |
| 只分析前 | 0–3600 秒，整数；默认 0，显示“整首歌曲” | 0 表示不截取，处理整首文件；非零只分析从文件开头开始的 N 秒。用较短片段可先检查输入和结果。3600 是非零输入上限，不是“整首歌曲”模式的长度上限；它也不能指定中间某段的起点。 |

选择“论文参数（兼容读取）”时，程序使用 FFmpeg 读取原采样率音频，声道平均后交由 torchaudio 重采样；“默认”路径由 FFmpeg 读取为模型所需的 24 kHz 单声道。无需先手动把文件转为这一规格。

### 8.3 高级：窗口与导出

点击“高级：窗口与导出”展开。窗口长度固定为 300 秒；不是由下方两个数值决定窗口长度。

| 中文界面名称 | 范围与默认值 | 生效条件、用途与调整影响 |
|---|---|---|
| 窗口重叠 overlap | 0–290 秒；默认 200 秒 | 仅在“默认”预设中使用。决定相邻窗口共享多少音频，常规前进步长为 300−overlap 秒。增加重叠会减小前进步长、增加长音频的处理量；减小重叠会减少跨窗口共有上下文。重叠过大还可能让用于延续识别的 token 前缀占满上下文。 |
| 右侧上下文 lookahead | 0–290 秒；默认 100 秒 | 仅在“默认”预设中使用。非最后一个窗口把尾部这段音频作为向右参考，暂不把该尾段作为本窗口最终接收的结果。提高它会改变接收边界和可参考的未来音频范围；不代表向成品添加静音或延迟。必须满足 lookahead≤overlap。最后窗口接收剩余音频。 |

“默认”预设开始前会检查 `0 ≤ lookahead ≤ overlap < 300`，例如 overlap=50、lookahead=100 不能运行。常用起点是 200／100；有明确窗口边界问题时再做对照调整。300 秒以内的音频只需要一个窗口，这两个参数主要影响长歌曲如何分窗与拼接。

切换为“论文参数（兼容读取）”后，窗口输入框可能仍显示之前的数字；本次运行会忽略手动数字，实际使用 100／0。切回“默认”时，手动参数重新参与运行校验。窗口边界的具体位置还会受到末尾不足一个窗口时的收尾安排影响。

四个导出选项均默认不勾选，面向需要分析模型中间结果的用户；只想获得乐谱和 MIDI 时可以全部关闭。

| 中文界面名称 | 勾选后保存什么 | 用途与代价 |
|---|---|---|
| 导出 logits | 每个生成位置的原始 token 预测分数，以及对应 token 位置 | 用于研究模型在生成某个音乐 token 时如何评分。它不是最终音符正确率，原始 logits 也不是概率。会增加导出数据量与磁盘写入。 |
| 导出 token 分数 | 经过生成约束掩码处理后的 token 分数，以及对应位置 | 用于查看在音乐语法约束下哪些 token 仍可被选择，适合和 logits 对照。不要把数值直接解释为逐句或逐音符置信度。 |
| 导出音频/解码器特征 | 音频编码特征、帧时间及有效帧标记；另导出解码器隐藏状态、输入 token 和位置 | 用于把音频帧与音乐解码过程对应起来。解码器特征会额外分批计算和保存，因此除了磁盘空间也可能增加处理时间。只勾选此项不会自动包含 MERT 的全部 24 层。 |
| 导出 MERT 全部 24 层特征 | 分窗口的 MERT 24 层音频特征，以及音频特征文件中的相关状态 | 需要逐层研究时使用，通常比只保存少数特征占用更多空间。可独立勾选；仅勾此项不会额外导出解码器特征。若同时需要解码器状态，再勾选上一项。 |

张量位于本次输出目录的 `tensors/window-0000/`、`window-0001/` 等子目录。`index.json` 记录窗口起止与文件清单；`audio.safetensors` 存音频特征；`tokens-*.safetensors` 存所选预测分数；`decoder-*.safetensors` 存解码器状态。文件只会在对应选项开启时出现。不同窗口的重叠音频可能重复出现在这些数据中，不能不看时间信息就当作一条无重叠时间轴拼接。

### 8.4 如何阅读结果

| 区域或页签 | 含义与使用方法 |
|---|---|
| 分析概览—调性 | 显示识别到的调性摘要，最多显示前两个不重复调性。完整的分段调性请查看输出中的 `key.lab`，不能把摘要当成整首歌每一时刻的调性。 |
| 分析概览—速度 BPM | 由已识别节拍之间的正时间间隔取中位数，再换算的概括值，并非逐段速度曲线。 |
| 分析概览—拍号 | 概括显示首个已解析节拍的拍号。缺少足够节拍时，BPM 或拍号可能显示“—”。 |
| 分析概览—时长 | 本次实际分析音频的时长；设过“只分析前”时应按截取范围理解。 |
| 分析概览—音符 人声/器乐 | 两个数依次为人声旋律、器乐旋律的音符数量；不是两个音频轨的响度或时长。 |
| 彩色段落时间条 | 按时间比例显示前奏、主歌、副歌、桥段、尾奏等结构。鼠标移到色块上可查看原始标签及起止时间；颜色用于区别标签。相邻、同标签且间隔很小的结构会在此合并显示。 |
| 🎼 乐谱 | 查看生成的乐谱。若音符或结构需要修正，使用“在乐谱编辑中打开”；本页用于查看分析结果。乐谱视图的通用控制见相应通用说明。 |
| ABC | 查看只读 ABC 源文本。ABC 适合继续编辑及作为后续创作条件；未能生成时此处显示原因。 |
| 和弦进行 | 每行包含开始、结束、易读和弦名、原始标签。比如 `C:min` 显示成 `Cm`；`N` 或 `X` 显示“—”，应结合原始标签理解。表格不能直接编辑。 |
| 段落结构 | 逐行显示起止时间、中文段落名和原始结构标签，适合核对主副歌切换位置。表格不能直接编辑。 |
| 输出文件 | 显示本次输出的相对文件名，双击由系统关联程序打开。 |
| 诊断信息 | 查看错误、ABC 错误、警告、乐谱整理诊断、峰值显存及输出目录。某些音符为了生成单声部记谱视图会被调整，原始预测仍另外保留；出现诊断不等于所有结果都不可用。 |

一次运行可能已经保存了事件、MIDI 和 LAB，但未能生成 ABC。此时“发送到 AI 翻唱”和“在乐谱编辑中打开”不可用，“打开输出文件夹”仍可用。先查看 ABC 错误和警告，确认缺失的是乐谱生成步骤还是音频／模型分析整体失败。

| `tokens.txt`、`tokens.json` | 各窗口生成的音乐 token，用于核查窗口与解码过程。 |
| `result.json` | 本次分析元数据，包括预设、实际精度、时长、窗口安排、警告与统计等。 |
| `playback.json` | MIDI 播放轨、音符、小节映射与播放警告。 |
| `notation/` | 为记谱整理的中间旋律 MIDI、节拍、和弦、调性与结构数据。它们可能经过记谱所需整理，与原始事件用途不同。 |
| `tensors/` | 高级开关选中的模型张量；未启用对应导出时不会有对应文件。 |

“🎙️ 发送到 AI 翻唱”把本次分析结果交给翻唱页；“🎼 在乐谱编辑中打开”把 ABC 带入编辑页，并按本次“仅旋律”选择设置相应编辑模式；编辑页原有的风格与歌词输入会保留。“📂 打开输出文件夹”打开本次运行目录。

“📄 导出乐谱 / 钢琴 WAV”打开第 12 章的通用导出窗口。有本次结果时会带入输出目录；也可以选择以前的结果，无需再次扒谱。此入口与“开始扒谱”相互独立，具体输出格式、渲染方式和音频选项见第 12 章。

## 9. 歌词识别

“🎤 歌词识别 · Qwen3-ASR”识别歌曲中的演唱文字，再按需要用 Qwen3-ForcedAligner 生成字／词时间信息，整理成可编辑的 YuE2 歌词和逐行 LRC。带伴奏歌曲也可作为输入，但应试听核对人声较弱、混唱、同音字、重复句和专有名词等位置。

### 9.1 识别与核对的完整流程

1. 在“歌曲音频”中拖入或选择一首歌曲，先用播放器确认文件。
2. 已知演唱语言时选对应语言；不确定或中英混唱时可先用“自动识别”。按需要填写歌名、人名等“提示信息”。
3. 如果需要逐行时间轴、停顿断句、段落对应或 LRC，保持“逐字时间戳对齐”开启；只需要文本时可关闭。
4. 选择“段落标签”：需要主歌／副歌等原曲结构时用 SheetSage2；只需先快速获得文字和简单分段时用“按停顿分段”。
5. 点击“🎤 识别歌词”。完成后先调整断句参数，再逐行试听并修正歌词文字；这样可以保留自动重新排版能力。
6. 查看“LRC”页签是否仍能安全复用时间轴，再用“💾 保存…”保存修订文本或 LRC，或发送到翻唱／创作页。

结果提示中的“识别用时”是 ASR／对齐阶段的计时，不包含前面全部模型加载和 SheetSage2 结构分析耗时。“时长”则是歌曲长度，两者含义不同。

### 9.2 识别选项逐项说明

| 中文界面名称 | 选项、范围与默认值 | 生效条件、用途与调整影响 |
|---|---|---|
| 演唱语言 | 默认“自动识别”；还可选中文、粤语、英语、日语、韩语、法语、德语、西班牙语、俄语、葡萄牙语、意大利语、泰语、越南语、印尼语 | 指定语言会给 ASR 强制语言条件，适合自动识别误判时纠正；选错语言可能导致错误或无结果。自动识别也可用于混唱，结果仍需核对。界面显式选项以此列表为准，页面介绍中的模型多语言能力不等于所有语言都有独立下拉项。 |
| 提示信息 | 可选文本；默认空 | 给识别模型的上下文，例如歌名、歌手姓名、地名、生僻词。用于帮助识别专名，不是待对齐的完整歌词输入，也不是修改已识别文本的按钮。提示不保证被正确采用。 |
| 逐字时间戳对齐（Qwen3-ForcedAligner，用于断句、分段、LRC） | 默认开启 | 开启会使用额外对齐模型，生成字／词时间，再汇总为逐行开始和结束时间。关闭后只识别文本，按标点／原换行整理；段落选项禁用，不能生成有效的时间轴 LRC。缺少对齐模型时可以关闭它先识别文字。 |
| 段落标签—按停顿分段 | 可选；默认未选 | 仅在对齐开启时有意义。不额外运行 SheetSage2；根据已对齐歌词行之间的长停顿分段，统一使用 `[Verse]`。当前分段阈值固定为 4 秒，与下方“停顿超过此值换行”是两个不同阈值。 |
| 段落标签—用 SheetSage2 识别段落（推荐） | 默认选中 | 仅在对齐开启时使用。先为原曲分析结构并生成仅旋律乐谱，再把有时间轴的歌词行对应到前奏、主歌、副歌等标签。因此需要 SheetSage2 及其主干模型，并增加这一分析步骤。这个页面没有单独的 SheetSage2 精度／窗口选项，使用引擎的默认扒谱参数。 |

对齐模型的语言覆盖与 ASR 不同。本地模型说明列出的对齐语言为中文、英语、粤语、法语、德语、意大利语、日语、韩语、葡萄牙语、俄语、西班牙语。泰语、越南语和印尼语虽有 ASR 语言选项，但不在这一对齐语言列表中，宜先关闭对齐取得文字，不能承诺同样获得可用的时间轴。

这页没有“只处理前 N 秒”的时长框；它会读取所选歌曲，较长音频由识别库内部切片处理。播放器跳转不会改变识别范围。页面也没有供用户输入一份现成歌词后单独进行强制对齐的入口。

### 9.3 断句参数及识别后的重新排版

点击“断句参数（识别后调整会立即重新排版）”展开。

| 中文界面名称 | 范围与默认值 | 用途、联动与调整方法 |
|---|---|---|
| 停顿超过此值换行 | 0.1–5.0 秒；步长 0.1 秒；默认 0.6 秒 | 控制同一句中遇到较长停顿时是否拆成新行。减少数值通常会得到更多短句，提高数值更倾向于保留连贯长句。算法还考虑标点、行宽与极短句，因此并非每个超过阈值的停顿都会独立换行。 |
| 每行最多（英文单词算 2） | 6–60 字；默认 22 | 控制分行的目标宽度。中文等字符按字符长度计，非中日韩字符开头的对齐单元按 2 计，界面以英文单词说明。缩小可得到适合逐句校对的短行，提高可减少换行。它是排版尺度，不是模型最多识别多少字。 |

实际断句同时参考原始 ASR 标点。原文含句读标点时，停顿断句阈值至少为 1.5 秒，以减少拖长音造成的过度切句；此时把“停顿超过此值换行”从 0.6 改到 0.3 秒，可能看不出变化。算法也会避免仅靠停顿切出过短前句，并可能把紧邻前句的极短尾句合并，因此最终个别行可略超“每行最多”的数值，最多允许至该值加 4 的合并宽度。

自动重排需要已经有识别结果且有对齐时间信息。未开启对齐时，分行依据标点和原换行，上述两个参数不会重新生成时间轴。识别后只调整这两个参数，程序会即时重建 YuE2 歌词、逐行时间轴和 LRC 预览，无需重新跑模型。

如果已经手动修改了歌词文字，程序会保留修改，提示“没有按新的断句参数重新排版”。可以先用 Ctrl+Z 撤销到自动识别结果再调参数；也可以保留手动排版，继续编辑和保存。调整“演唱语言”“提示信息”“对齐”或“段落标签”只影响下一次识别，不会自动重跑已有结果。

### 9.4 四个结果页签

| 页签 | 如何使用 |
|---|---|
| YuE2 歌词（可编辑） | 在这里校对同音字、漏词及段落标签，一行一句。此处当前文字是复制、保存 TXT、发送到翻唱／创作的来源。 |
| 逐行时间轴 | 只读表格，显示每行开始、结束及文字。双击某行会把原曲播放位置移到该行开始前约 0.2 秒并播放，便于听辨。没有时间戳的行显示“—”，不能凭双击建立时间戳。 |
| LRC | 只读的逐行时间标签预览，形式为 `[mm:ss.xx]歌词`，使用该行开始时间，保留到百分之一秒。它不是逐字卡拉 OK 文件，也不包含每字高亮和结束时间。 |
| 原始识别文本 | 只读保存模型识别文字，适合对照自动断句和手工修改；不会随着编辑器修订而改写。 |

**修字后如何保持 LRC 可导出**：程序把编辑后的非空、非独立段落标签行，按行号与识别时间轴一一配对。保持实际歌词行数不变时，修订文字会同步进入 LRC 和时间表，仍复用原始行时间。空行和单独的 `[Verse]` 等标签行不计入歌词行数。

如果增加、删除、合并或拆开了实际歌词行，LRC 页会提示行数不一致，“保存…”导出 `.lrc` 时会阻止保存。此时逐行时间轴仍显示原识别行，不能把它当作当前手改文字的时间轴。即使行数碰巧相同，若交换了行序或大幅重写内容，也只是按行号复用时间，并不会重新对齐；应逐行试听确认后使用。保存 TXT 不要求有时间轴。

## 10. 音乐特征

“🧬 音乐特征 · MERT-v2”将音频编码为数值特征，提供歌曲自相似结构图、多首歌的余弦相似度，并保存 `.npy` 数据供后续研究使用。当前模型有 24 层，每帧特征为 1024 维，名义时间分辨率约 25 帧／秒。

这一页输出的是音乐表征和基于表征的比较结果。层选择指南里的“流派”“情绪”“乐器”等是下游研究任务名称，选择它们不会直接得到流派名称、情绪标签、乐器清单或和弦谱；具体的下游预测还需要相应模型或分析流程。

### 10.1 文件管理与提取流程

1. 先选“模型”。不确定时从默认的 MERT-v2-FullSong 开始。
2. 拖入一个或多个音频，或拖入整个文件夹。也可以点“＋ 添加文件”多选文件，或“＋ 添加文件夹”选择目录；文件夹会递归查找支持扩展名的音频。
3. 列表可多选；“移除所选”只移走选中条目，“清空”移走全部列表条目，都不会删除磁盘源文件。重复添加相同路径不会再加入一份。
4. 选择输出层、时长限制、精度与保存开关。多首歌的可比性依赖相同设置，最好放在同一次任务中提取。
5. 点击“🧬 提取特征”，完成后从“结构自相似图”的“歌曲”下拉框切换查看，或转到“歌曲相似度”比较。
6. 用“📂 打开输出文件夹”或“输出文件”页签取出 `.npy` 和 `summary.json`。

添加、移除、切换模型和调整参数只改变下一次提取输入；已有图表不会因此自动重算，需再次点击“提取特征”。列表为空时不能启动。多文件按顺序处理，“停止”请求取消；若中途取消或某一文件失败，先前已经写出的文件可能存在，但没有完成汇总时不能视为整批相似度已经计算成功。

### 10.2 两种模型怎么选

| 模型 | 默认与处理方式 | 适合如何使用 |
|---|---|---|
| MERT-v2-30s | 非默认；以 30 秒上下文处理。长音频按 30 秒片段分别编码，结果帧按原顺序拼接。 | 需要采用该模型表征，或按下游层指南做音乐理解研究时使用。片段间没有本页可调的重叠或跨片段上下文设置。 |
| MERT-v2-FullSong | 默认；本地模型面向 30–360 秒歌曲上下文；当前配置以 360 秒为分片窗口，超过窗口的音频继续分片处理。 | 查看较长范围的歌曲结构和整首表征，或希望采用 SheetSage2 主干同系列编码器表征时使用。它的名称不代表任意长音频都在一个无限窗口内处理。 |

两个模型输出维度相同不代表数值空间完全相同。跨模型直接比较已有向量会混入模型差异；比较一组歌曲时，应使用同一模型和同一层。页面模型说明中的公开评测文字属于模型背景，不能当作当前歌曲的准确率。

### 10.3 特征设置逐项说明

| 中文界面名称 | 选项、范围与默认值 | 生效条件、用途与调整影响 |
|---|---|---|
| 输出帧特征的层 | “最后一层（默认）”或第 1–24 层（L1–L24）；默认最后一层 | 帧级特征、歌曲平均向量、自相似图和歌曲相似度都取自这一层。L1 对应第一个模型块输出；最后一层对应末层输出。换层会改变这些表示与相似度，不能把不同层的分数直接混作同一标准。 |
| 快速选择 | 默认“按下游任务推荐层…”；任务选项见下表 | 按当前所选模型，把输出层切换为该任务的推荐层；选完后下拉框回到提示文字。它是设置快捷方式，不会运行对应任务分类器。先选模型，再选任务；随后切换模型不会自动再次套用原任务推荐，应重新选择一次。 |
| 只处理前 | 0–3600 秒，整数；默认 0，显示“整首” | 0 处理整首；非零对列表内每首歌都只处理从开头开始的 N 秒。可用于控制试验规模，但比较结果将仅代表各自开头片段；不同歌曲的开头若分别是静音、前奏或副歌，含义也不同。3600 是非零输入上限，不是整首模式的硬性时长上限。 |
| 计算精度 | BF16 快速／FP32 精确；默认 BF16 | CUDA 上 BF16 启用混合精度，FP32 关闭它；CPU 实际为 FP32。结果 `.npy` 统一转为 float32 保存，所以选 BF16 不代表 `.npy` 元素一定按 BF16 保存。精度选择可能影响数值与资源开销，不保证改变后任务效果更好。 |
| 保存帧级特征 frames.npy [帧数, 1024] | 默认开 | 为每首保存所选单层的逐帧数组。后续需要时间变化、自己重算结构图或帧级任务时保留。关闭仅减少磁盘导出，本次程序仍计算帧特征以生成歌曲向量和图表。 |
| 保存各层平均向量 layers.npy [24, 1024] | 默认开 | 保存全部 24 层各自在时间轴上的平均向量，每行一层。适合需要多层整首表示的研究。关闭只是不保存此文件；不会让本次推理只计算一层。 |
| 歌曲级向量 embedding.npy [1024] | 无关闭开关；始终保存 | 所选层的所有有效输出帧取平均，作为整首或所截取片段的表示；歌曲相似度依据它计算。长音频各片段按帧数量共同汇总，并不是把每个片段不分长度地等权平均。 |

“保存各层平均向量”包含 24 层平均结果，但不包含每一层每一帧的完整时间序列。当前页面没有“导出全部 24 层帧特征”的开关；`frames.npy` 始终只有“输出帧特征的层”所选一层。快速选择命中“全部层”时，会把输出层设回“最后一层”，并勾选保存 `layers.npy`；请按这个实际行为理解提示。

### 10.4 结构自相似图怎么读

上方“歌曲”下拉框列出本次成功处理的音频，同时显示处理时长和输出帧数；选择一项后查看该歌曲的图。横轴、纵轴都表示这首歌的时间，每个格子比较两个时间片段的特征余弦相似度。鼠标悬停可查看两个时间位置及具体数值。

主对角线比较每个片段与自身，通常最亮。对角线之外重复出现的亮块或斜线，可能提示相似的副歌、重复动机、相近配器或其他重复内容；它是核对结构的线索，不会自动给出“此处是副歌”的文字结论。先找到亮块对应的两个时间范围，再回到音频核实比较可靠。

图中会对帧做时间平均，通常约每秒一个格子；为控制图尺寸，长音频会进一步合并，矩阵一边最多约 480 格。非常短的输入会使用更细粒度。图的颜色针对当前矩阵作拉伸，不同歌曲两幅图的相同颜色不一定代表相同的原始数值，应查看悬停值而非仅凭亮度横向比较。图中时间范围还可能省略不足一个汇总块的极短尾部。

这一页没有图上双击播放或导出 PNG 的专用按钮。自相似矩阵用于当前界面显示，并未另外自动写成 `ssm.npy`；需要后续重算时保留对应 `frames.npy`。

### 10.5 歌曲相似度怎么读

至少添加两首歌，才有有意义的跨歌曲比较。表格的行、列都是音频名称，每格显示两个歌曲向量的余弦相似度，保留三位小数；鼠标悬停可看完整名称和四位小数值。矩阵关于主对角线对称，一首歌与自身通常为 1。

分数接近 1 表示两个向量方向接近；“1”并不能证明两个音频文件字节相同，也不是“百分之百是同一首歌”。余弦相似度的理论范围为 −1 到 1，不是百分比。可在相同模型、相同层和相同截取策略下按分数比较候选歌曲，不宜直接用某个固定阈值判断抄袭、版权关系或旋律是否完全一致。

表格颜色依据本次矩阵的分数范围显示相对差异；不同批次颜色不能直接比较，应记录实际数值及设置。只有一首歌时仍可能看到 1×1 自比较结果，这不提供跨歌曲结论。

### 10.6 输出文件与复用

文件名以序号和歌曲名组成，例如 `01_歌曲名.frames.npy`，并非所有文件都直接名为 `frames.npy`。非法字符会被整理，同名歌曲会通过序号区分；界面名称在需要时附加父目录帮助辨认。

| 文件 | 保存条件与含义 |
|---|---|
| `序号_歌名.frames.npy` | “保存帧级特征”开启时写入；float32，形状 `[T, 1024]`，T 为本次实际输出帧数。每行表示所选层一个时间位置的特征，不是一个音符或一句歌词。 |
| `序号_歌名.embedding.npy` | 始终保存；float32，形状 `[1024]`，所选层帧向量的时间平均。 |
| `序号_歌名.layers.npy` | “保存各层平均向量”开启时写入；float32，形状 `[24, 1024]`，按 L1–L24 顺序排列。 |
| `summary.json` | 整批完成后保存模型变体、所选层、实际精度、帧率、各文件信息、时长、帧数、图的时间汇总尺度和歌曲相似度矩阵。它不包含完整自相似矩阵或全部帧数据。 |

“输出文件”页签列出本次目录文件，双击交给系统关联程序打开。`.npy` 是 NumPy 数值数组，通常应在支持该格式的分析工具中读取，不能作为音频播放，也不能直接当作 YuE2 歌词或 ABC 乐谱。

音频按模型窗口切片时，短到达不到模型最小输入要求的尾片会被略过；整个音频都过短会报错。因此帧数是程序实际提取数量，应以结果记录为准，不要只用“显示时长×25”推定精确数组行数。当前页面没有从已有 `.npy` 或 `summary.json` 恢复图表的入口；磁盘文件可供外部工具使用，页面内重新查看需重新提取。

## 11. 作品库与任务恢复

### 11.1 作品库包含什么

作品库统一浏览当前输出根目录下 `songs` 文件夹中的直接子目录，包括歌曲草稿、只完成规划的任务、未完成生成、已完成歌曲和重新解码作品。扒谱分析、歌词识别、音乐特征分析的专用输出目录不属于此歌曲列表。

左侧每项显示标题、类型、乐谱模式、种子、时长和日期。有新任务记录的作品还显示任务状态、最新保存阶段，以及批量任务的数量。标题优先使用填写的作品名；未填写时通常取歌词第一句，否则采用文件夹名。目录按名称逆序显示，标准自动命名目录通常让较新的作品排在前面。

### 11.4 哪些阶段能恢复

“继续任务”复用的是完整保存的阶段，不是暂停瞬间的任意内部进度。状态和阶段表示不同信息：例如“已取消 · 歌曲 tokens 已保存”说明上次被取消，但歌曲 tokens 阶段已经可用。

| 最新保存阶段 | 已保留内容的意义 | 继续后主要工作 |
|---|---|---|
| 输入草稿 | 风格、歌词、参数及可能提供的 ABC。 | 从规划/处理提供的乐谱开始，再生成歌曲、声学结果和音频。 |
| 乐谱已保存 | 完整乐谱规划及相关上下文。 | 生成歌曲 tokens，再声学合成和解码。 |
| 歌曲 tokens 已保存 | 歌曲生成阶段已经完成。 | 声学合成，再解码。 |
| 声学结果已保存 | 已有完整 `latent.npy` 潜变量。 | 继续音频解码。 |
| 音频已完成 | 已有主音频及结果记录。 | 单首已完成任务无需继续；批量主任务可能仍需完成其他成员。 |

任务状态可能显示“草稿”“待继续”“运行中”“已取消”“失败，可继续”“已完成”。程序上次意外退出后，旧记录仍写着运行中但实际已没有进程占用时，会显示“已中断，可继续”。“可继续”表示有恢复入口，不保证文件、模型和环境已经全部通过恢复校验。

操作顺序：在作品库刷新 → 选中任务 → 查看保存阶段及上次错误 → 点击“继续任务” → 等待完成。恢复中仍可查看进度和停止；失败后查看新的错误提示，再处理对应原因。

#### 11.4.1 继续时哪些参数会沿用

继续使用该任务保存的风格、歌词、ABC、种子、ODE、CFG、采样、解码设置及模型选择等。改了创作页、翻唱页、编辑页当前输入，不会改变作品库中旧任务的快照；改了设置页的模型选择，也不会把旧任务自动迁移到新模型。

显存预算使用设置页的当前值，便于在内存条件变化后重试。希望换解码器或解码方式时，优先使用“重新解码”新建作品；希望改变文本、旋律、采样或生成长度时，载入参数或乐谱后新建歌曲任务。

#### 11.4.2 恢复边界

- 当前阶段尚未完整保存就停止或异常退出时，重新执行该阶段；不会从半个 token 序列、半次声学合成或半个解码块接上。
- 任务文件缺失、损坏或被手动改动，可能使校验失败。恢复完整备份，或载入能使用的参数/乐谱重新生成；不要通过手改任务状态声称阶段已经完成。
- 已完成阶段对应的推理代码版本发生变化时，旧阶段可能被拒绝复用；模型权重变化也可能阻止续跑。已有有效 latent 时可以通过独立“重新解码”创建新作品。
- 保存任务指定的本地模型不存在时，需要恢复相应模型，不能仅靠选择另一个名字替代它继续。
- 另一个窗口或进程正在写同一任务时，程序会阻止并行续跑；等待该任务结束后再操作。
- 已完成但达到长度上限的歌曲不会因“继续任务”自动续写。调整输入或采样后新建任务。

### 11.5 多版本任务怎样恢复

一次生成多首时，每首都有自己的目录和阶段记录；主任务记录整个批次的成员。中途停止后，可以选主任务“继续任务”，跳过已完成的歌曲，继续未完成成员。也可以在列表中选某个子任务单独继续。

种子按初始种子、初始种子 + 1、初始种子 + 2 依次使用。数量上限为 16，种子序列不得超出允许范围；接近最大种子时应减小初始种子或数量。

主任务的第一首已经显示“音频已完成”，不必然代表整个多版本批次全部完成，要结合详情中的批量说明和“继续任务”是否可用判断。结果和作品库中各首都可以单独试听、编辑或导出。

### 11.6 重新解码：复用声学结果输出另一份音频

重新解码只把已生成的声学潜变量转换为音频，不重新作曲、不重唱歌词，也不重新运行声学合成。它适合改变解码器或解码方式、从已保存的声学结果恢复音频，以及对比解码结果。

有两个入口：选择已有作品后点击“重新解码”，或者顶部“载入 latent 重新解码”并选择 `.npy` 文件。弹窗包含：

| 控件 | 含义 |
|---|---|
| 潜变量路径 | 显示本次输入文件。 |
| 本地解码器 | 列出本地模型目录中识别为 YuE2 VAE 的解码器，初始优先选择设置页当前配置；只列出名称并不代表模型权重一定完整。没有可选项时“开始重新解码”不可用。 |
| 音频解码设置 | 自动、分块、完整解码，以及分块长度和上下文长度；参数与启用条件见第 4 章。 |
| 开始重新解码 | 校验输入和本地解码器后开始新任务。 |
| 取消 | 关闭弹窗，不创建本次解码结果。 |

该弹窗使用自己的解码默认设置；它不会自动把所选作品上次的解码设置完整复制过来。请确认弹窗中的模式和数值，再开始比较。

#### 11.6.1 latent 文件要求

潜变量必须是 YuE2 对应的 NumPy 浮点数组，形状为 `[T, 64]`，`T` 至少为 1。数组必须全是有限数，不能含 NaN 或无穷值，转换为 float32 后也不能溢出。音频 WAV/FLAC、MIDI、任意模型的特征向量、把其他文件改成 `.npy`，都不能当作有效输入。

如果选中标准作品目录里的 `latent.npy`，程序会利用任务记录或结果清单检查来源。新任务必须已经完整完成声学合成，不能拿尚未登记为完整阶段的临时 latent 复用；已知文件大小或校验值不一致时也会拒绝解码。读取期间来源文件发生变化，会要求重试。

对于外部孤立 `.npy`，能通过形状和数值检查并不自动证明它来自兼容模型，应使用真实的 YuE2 声学结果及匹配解码器。

#### 11.6.2 输出及恢复

重新解码会在当前歌曲输出目录下创建一个新的“重新解码”作品，原作品保持不变。新作品保存自己的 latent 副本、解码参数、任务状态、音频与结果记录；能从标准来源获取到的风格、歌词、标题和 ABC 也会随来源信息保留。孤立 latent 没有这些文字信息时，作品详情可能不完整，但不影响其作为有效声学输入解码。

主音频仍为 48 kHz 双声道 FLAC，可在作品库试听、导出 MP3，或再次重新解码。需要钢琴或谱面输出，仍要有对应 ABC。

解码任务也有可恢复阶段：如果在来源 latent 尚未完整复制进新任务前中断，继续时仍需要原文件存在且内容保持一致；已保存为“声学结果已保存”后，会使用新任务中的 latent 副本。更换源文件或解码器应创建新解码任务。

### 11.7 删除、备份与旧作品兼容

“删除”会先显示完整作品文件夹路径并要求确认。确认后永久删除整个所选目录及其中的音频、MP3、乐谱、参数和阶段文件，不进入回收站。它只删除当前输出 `songs` 下的直接作品目录，不能用来删除任意路径或链接目录。

删除时程序会停止占用该目录音频的内置播放器；文件仍被其他程序占用时可能删除失败，应关闭外部播放器或相关程序后重试。多版本任务的成员是多个独立目录，删除当前一项不会自动删除整个批次。保留恢复能力时，应一起备份主任务及关联子任务目录。

旧作品没有 `job.json` 时，作品库仍尝试从 `meta.json`、`request.json`、`score.abc` 与 `audio.flac` 读取可用信息：有歌词可复用参数，有 ABC 可编辑或导出，有音频可试听或导出 MP3。但旧格式目录不会凭空获得新格式的逐阶段续跑能力。

只有 ABC 的旧目录可以载入编辑，之后补充风格与歌词并保存为新草稿。只有音频、没有参数和 ABC 的普通文件夹不会自动成为可编辑作品；只有 latent 时使用顶部的导入解码入口。

部分参数或记录格式错误的目录会显示“文件有误，无法继续”，详情显示错误。此时生成、编辑、解码等操作受限，仍可打开文件夹检查或删除。列表能显示某项也不表示所有大文件已经通过完整校验；正式载入或续跑时仍可能提示文件缺失或损坏。

备份应保留完整目录，不只复制 `audio.flac` 或 `score.abc`。若手改已保存的任务文件导致校验失败，保留原件并从可读的参数或 ABC 新建作品，比直接篡改阶段记录更适合继续创作。

## 12. 导出乐谱、钢琴 WAV 与 MP3

### 12.1 三种导出不要混淆

| 产物 | 需要什么输入 | 内容 |
|---|---|---|
| PDF／PNG／SVG | ABC 乐谱 | 五线谱图形，适合查看、排版或打印 |
| 钢琴 WAV | MIDI 文件 | 用钢琴音色演奏 MIDI；不是 YuE2 的真实歌声音频，也不是原曲分离音轨 |
| MP3 | 已生成的 FLAC／WAV 等音频 | 将已完成的音频转码成便于分享的 MP3，不会重新生成歌曲 |

### 12.2 打开“导出乐谱与钢琴预览”

扒谱分析完成后，点击“导出乐谱 / 钢琴 WAV”；也可从乐谱编辑、结果面板或作品库打开相应乐谱导出入口。已有分析结果可直接导出，无需重新加载模型或重新扒谱。

1. 确定是导出当前编辑器里的乐谱，还是导出已有结果文件夹。
2. 检查 ABC 和 MIDI 的来源，按需要选文件。
3. 勾选要输出的乐谱格式；如需钢琴音频，再勾选“钢琴 WAV”与声部。**只有 MIDI 时，取消 PDF／PNG／SVG，只勾选钢琴 WAV 和至少一个声部**，否则仍会要求 ABC。
4. 检查“保存位置”，点击“开始导出”。
5. 完成后点击“打开导出文件夹”。

### 12.3 所有输入和选项

| 控件 | 初始行为／选择范围 | 说明 |
|---|---|---|
| 结果文件夹 | 从调用入口带入，或点击“选择…” | 自动寻找 `score.abc` 及可识别的 MIDI。如果目录里有多个候选且无法确定，单独指定文件。从编辑器打开后，要切换为另一个文件夹的乐谱，请点击本行“选择…”；它会清除带入的编辑器 ABC 和单独 ABC／MIDI 路径。只手填文件夹路径不会清除这些优先来源 |
| ABC 文件 | 可选，`.abc` | 单独指定要排版的乐谱。手填后离开输入框提交；指定 ABC 文件会替代从编辑器带入的乐谱来源 |
| MIDI 文件 | 可选，`.mid`／`.midi` | 钢琴 WAV 的来源；可以与 ABC 单独选择，但应自行确认它们确实对应同一版本 |
| 保存位置 | 初始为当前输出根目录下 `rendered` | 每次导出会在这里建立新子目录，不覆盖之前的渲染目录 |
| PDF | 初始勾选 | 整份乐谱包含在一个 PDF 中，适合阅读、打印 |
| PNG | 初始不勾选 | 按页生成位图，便于插入普通文档 |
| SVG | 初始不勾选 | 按页生成矢量图，放大或后期排版更方便 |
| 钢琴 WAV | 来源存在可用 MIDI 时自动勾选，否则不勾选 | 没有 MIDI 时需取消此项；仅有 ABC 的乐谱不能在这个导出入口自动转成 MIDI |
| 混合 | 初始勾选 | MIDI 中可用部分的综合钢琴试听 |
| 全部旋律 | 可多选 | MIDI 的旋律声部集合；不等同于带原音色的原曲旋律轨 |
| 人声旋律 | 可多选 | 识别为人声旋律的 MIDI 轨道，用钢琴演奏 |
| 器乐旋律 | 可多选 | 识别为器乐旋律的 MIDI 轨道，用钢琴演奏 |
| 和弦 | 可多选 | 和弦部分的钢琴试听 |
| 开始导出 | 需要至少一种产物 | 同时只运行一个此类导出任务；导出期间输入和选项暂时禁用 |
| 取消导出 | 当前任务运行时可用 | 请求停止渲染；已经生成的部分文件可能留在本次目录，不能将它们视为完整结果 |
| 打开导出文件夹 | 导出成功后，或失败／取消后且目录存在时可用 | 打开本次结果目录，核对文件和警告；正在导出时不可用 |

关闭导出弹窗或按 Escape 时，如果仍在导出，会先请求取消并等待；关闭主界面时也会处理运行中的渲染进程。

**当前编辑器 ABC 与原 MIDI 不会自动同步。** 例如把 ABC 中一个音高改了，再导出 PDF 会看到新音符；如果钢琴 WAV 仍选原 MIDI，它仍演奏原 MIDI 的音符。界面内 ABC 试听、ABC 排版、MIDI 导出钢琴 WAV 是三条不同的使用路径。

缺少某个 MIDI 声部时会提示跳过。可先勾选“混合”判断 MIDI 本身是否有效；不要把“没有人声旋律 MIDI”理解成原音频一定没有人声。

**外部 MIDI 的钢琴导出限制：** 当前渲染器不支持鼓轨，音符音高需要处于 MIDI 21～109，时间值必须合法。程序先校验整个 MIDI，再选择声部；即使只导出“人声旋律”，其他轨道里的鼓轨或越界音符也会导致失败。遇到这类提示，应先在 MIDI 编辑工具中移除不支持的轨道或修正音符，再导出。

### 12.4 MP3 导出

在有音频的结果面板或作品库中点击“导出 MP3”。码率取自“设置 → MP3 导出码率”，支持 320k、256k、192k、128k。

MP3 默认保存到原音频旁边，使用相同文件名、不同扩展名，例如 `audio.flac → audio.mp3`。**再次导出会替换同名 MP3**；如果想保留不同码率版本，请先把上一份重命名或复制出去。原 FLAC 不会因为转码而被改变。

## 13. 保存位置、文件用途和备份

### 13.1 输出根目录

未设置自定义目录时，输出在 `F:\AI\yue2_aibbs\outputs`。可以通过各页面的“打开文件夹”定位结果，通常不需要手动猜时间戳目录名。

| 根目录下的分类 | 常见内容 | 如何使用 |
|---|---|---|
| `songs` | 新歌、草稿、规划结果、多版本任务及重新解码的作品 | 从作品库查看；每个任务可能处于不同完成阶段 |
| `batch` | 批量创作／翻唱的批次状态及逐首中间结果 | 从“批量生成”的批次下拉列表继续；不要只备份最后一首音频 |
| `transcribe` | 扒谱的 ABC、MIDI、结构／调性／节拍文件及可选张量 | 可再次用于翻唱、编辑或离线乐谱导出 |
| `lyrics` | 歌词识别文本、时间戳记录和可选 LRC | 手动校对后保存；批量流程中的中间歌词也可能存在相应批次子目录 |
| `mert` | 帧特征、歌曲向量、各层均值、相似度摘要 | 用于分析或外部程序读取，不是可直接播放的音频 |
| `rendered` | 乐谱图形、钢琴 WAV、输入快照与导出记录 | 发送 PDF／图片，或试听 MIDI 钢琴版 |

### 13.2 常见文件名

| 文件 | 含义 |
|---|---|
| `audio.flac` | 已完成的 48 kHz 双声道歌曲音频 |
| `audio.mp3` | 由音频转码得到的分享版本；只有执行导出后才有 |
| `score.abc` | 文本乐谱，可在乐谱编辑页打开 |
| `meta.json` | 作品的输入和参数信息；供软件读取／复用 |
| `job.json` | 当前任务状态、输入及文件校验信息，决定能从哪一步继续 |
| `plan.json`、`plan_manifest.json`、`abc_tokens.npy`、`prefix.npy` | 已保存的完整乐谱计划相关文件；恢复时可能需要整组 |
| `semantic.npy` | 歌曲 token 阶段结果 |
| `latent.npy` | 声学潜变量，合法且完整时可重新解码 |
| `batch.json` | 批量生成页面的批次配置与每首状态 |
| `lyrics.txt` | 按段落整理、可供 YuE2 使用的歌词 |
| `raw.txt` | 原始识别文字，便于对照 |
| `lyrics.lrc` | 有可用时间对齐时保存的同步歌词 |
| `asr.json` | 识别／对齐结果、分行和结构信息 |
| `*.frames.npy` | 单个所选 MERT 层的逐帧特征 |
| `*.embedding.npy` | 歌曲／截取音频的时间平均向量 |
| `*.layers.npy` | 24 层各自的时间均值，不是全 24 层逐帧特征 |
| `render.json` | 乐谱／钢琴导出的状态、来源和结果记录 |

还会有模型版本、校验、采样配置、MIDI、分段标签及其他辅助文件，不要求用户逐个修改。任务未到达相应阶段时，缺少后续文件是正常的。

### 13.3 页面草稿、完整任务和备份的区别

- **页面草稿**：软件在合适时机记住输入，便于下次打开继续填写；主要保存在 `ui_settings.json`。它不能替代已经运行过的任务阶段文件。
- **完整任务草稿／作品**：通过保存草稿、生成或规划建立的任务目录，包含可复用输入和已完成阶段；在作品库管理。
- **导出的单个音频**：只够播放和分享，不足以恢复乐谱、参数、潜变量或批次状态。

需要以后恢复任务时，复制整个作品文件夹；多版本任务还要保留对应成员索引及子任务。批量创作／翻唱建议整体备份输出根目录，至少同时保留 `batch` 和 `songs`，避免批次引用的作品丢失。输入音频／歌词文件在尚未完成导入或分析时也可能仍被需要。

更换电脑或移动输出根目录后，不要只凭文件夹里仍有 JSON 就断定旧批次所有引用都有效；旧记录可能保存原路径，先检查并用小任务验证。模型或推理版本变化、阶段文件被修改／损坏，会使继续任务被拒绝。

### 13.4 表格未保存时怎样安全退出

编辑批次语言／风格时，软件会尝试保存。遇到临时占用、权限或磁盘空间问题，会保留输入并阻止依赖保存的操作。解决原因后，点击继续、刷新或再次关闭以重试；软件并不持续自动监听何时解锁。

如果此时关闭窗口，会询问是否放弃未保存的表格编辑，默认是“否”。选“否”留在窗口，选“是”明确放弃这些表格编辑后退出。若批次目标已不存在或当前记录已不接受修改，软件会说明无法保存并放弃该条编辑，当前切换／继续先中止，下一次操作可继续。

看到“已放弃”时，那段文字没有写入批次。重要长文本可先复制到单独文件，确认保存成功后再关闭。

## 14. 按目标选择操作流程

### 14.1 我只有歌词，想生成几个不同风格版本

1. 创作页导入或粘贴歌词。
2. 写一种风格，生成数量设为 1 或少量多版本，先得到基准结果。
3. 想比较唱法和旋律，保持风格不变只换种子；想比较风格，固定种子只改风格描述。
4. 给不同实验填写便于识别的作品名，完成后从作品库试听与导出。

生成数量会生成同一组输入的不同种子版本，不会自动为每个版本编写不同风格。需要每首不同要求时用批量页逐首设置。

### 14.2 我想给已有歌曲改词

1. AI 翻唱页选择原曲并扒谱。
2. 识别原曲歌词，逐行检查误字；最好先保存识别文字。
3. 在歌词编辑器里修改，或打开 AI 改歌词；同语言改词可先选择保持段落、行数和每行长度，跨语言可先保段落和行数。
4. 输入新风格或保持接近原曲的描述，然后生成新版本。
5. 对照原曲试听，检查旋律、歌词清晰度和结构；不满意再调整歌词长度、风格或种子。

此过程是参考乐谱重新生成，不能提供“原伴奏位级不变、原音调完全不变、只替换唱词”的保证。如果这三个条件都必须严格成立，当前入口不能完成该精确编辑目标。

### 14.3 我想先人工检查，再让几十首歌继续生成

先用第 6 章的批量页建立少量歌曲测试批次，选择审核模式，写词／改词完成后在审核窗口校正。确认调用服务、语言和风格都正确，再增加批次规模。恢复时使用“继续所选批次”，不要重复点击“开始新批次”来恢复旧任务。

### 14.4 我只想扒谱、拿 MIDI 或打印五线谱

到扒谱分析页运行，结果中查看 ABC 和 MIDI。需要 PDF／PNG／SVG 时打开导出窗口；要钢琴试听还要有 MIDI。无需再点生成歌曲。识别出的谱可能需要人工纠正，尤其是密集伴奏、鼓点和人声装饰音较多的素材。

### 14.5 我只想修复最后的音频解码

如果作品已保存完整合法的 `latent.npy`，在作品库重新解码，选择自动或合适的分块设置。它只重做音频解码，不能通过这个入口更改歌词、重新作曲或把陌生音频变成潜变量。

### 14.6 我想做短预览，再做长版本

短预览可以先使用少量歌词、生成数量 1、ODE 16，并按第 4.4 节降低歌曲最大 tokens。保留最小值不大于最大值。确认大方向后再使用完整歌词、ODE 32 与足够的 token 上限。

短 token 上限可能直接截断，不一定有自然尾奏；它也不能保证长版本前半段和短预览完全一致。需要复现某一任务时，请保存该任务和参数。

## 15. 常见问题与处理顺序

| 现象 | 先检查什么／怎么处理 |
|---|---|
| “还没有配置大模型” | 需要 AI 写词的入口尚未配置。到设置填写接口与模型并测试；如只是用现成歌词生成，可直接手写或导入 |
| HTTP 401／403／404 | 分别优先检查 Key、模型权限、接口地址／模型名称；切换预设后特别检查是否还留着上一个服务的 Key |
| HTTP 429／402 | 查看服务返回的额度、频率或余额信息；批量调用和重试会增加请求量。先小批次验证，不要连续重复启动相同大批次 |
| 本地接口连接不上 | 确认本地文本服务已经启动、端口正确、模型已加载；地址应是 API 入口，不是管理网页 |
| AI 只返回半段歌词 | 查看是否停止、网络流中断或服务输出限制；保留收到的文字，核对完整性后重试／继续改，不能把部分输出当完整歌曲歌词 |
| AI 改完没有变化到页面 | 是否点击了“应用到歌词”；弹窗右侧结果不会自动写回，改词本身也不会自动生成音频 |
| 歌曲太短或突然截断 | 检查歌曲最大 tokens、歌词长度和段落结构；适度提高上限。ODE／MP3 码率不是时长设置 |
| 歌曲反复唱一句 | 检查歌词是否重复、最小 tokens 是否被设得太高、采样是否异常；先恢复默认采样再比较种子，不要同时大幅修改全部参数 |
| 歌词没唱准／多字漏字 | 先修正 ASR 听写，缩短过长句、对齐段落结构；提高 CFG 或 ODE 不保证修复歌词准确性 |
| 翻唱伴奏和原曲不一样 | 这是重新编曲／演唱流程的正常可能结果；参考旋律或和弦并不冻结原始伴奏波形 |
| 显存不足 | 先看“设置 → 环境信息”的“声学合成注意力”是否为 cuDNN：若显示“分块计算”，把注意力内核改回“自动检测”。Windows 版 PyTorch 没有内置 FlashAttention，旧版本在声学合成阶段会退回整张注意力矩阵的算法，长歌额外占用 7～14 GiB；当前版本已改用 cuDNN，实测 3 分 43 秒的歌在 16 GiB 预算内完成。仍不足时：关闭其他占显存程序（如 ComfyUI），开启自动卸载，避免过低的 YuE2 预算；卡在解码时尝试自动或更小分块。不要靠增大预算超过物理显存解决 |
| 选了 1～3 GiB 预算无法生成 | 界面数值框允许输入，但 YuE2 生成校验要求非零至少 4 GiB；实际运行仍可能需要更高资源。可恢复 0，再按设备情况调整 |
| 按停止后还在运行 | 模型可能正在结束本次前向、对齐或解码块；先等待日志变化。强制结束会失去当前尚未完整保存的阶段 |
| “任务正在被另一个窗口或进程使用” | 检查是否另一个软件窗口仍在运行该任务；等待释放再继续。不要靠删除锁文件来同时运行同一任务 |
| 表格输入保存失败 | 按提示解决占用、读写权限或磁盘空间，再明确重试；关闭时默认保留。看到“已放弃”表示该条未保存，详见第 13.4 节 |
| 作品库为空／旧作品不见了 | 检查输出目录是否改过、搜索词和筛选条件是否还在；点击刷新。切换输出目录不会搬移旧文件 |
| 继续任务提示文件损坏／版本不同 | 恢复完整备份，或把可用歌词／ABC 载入编辑器建立新任务；不要手改校验信息强行续跑 |
| 只生成乐谱却没有 audio.flac | 该操作只保存规划结果，之后需按乐谱生成，才有可播放歌曲 |
| 音频不能播放／读入失败 | 检查文件存在且未损坏、FFmpeg 位于 `env\ffmpeg\bin`、当前文件确有音轨；能选中的扩展名不保证文件内部编码一定有效 |
| 五线谱能显示但试听无声 | 界面试听需要网络音色；检查系统／页面音量及网络。已有 MIDI 可使用离线钢琴 WAV 导出另行检查 |
| 导出提示没有 ABC／MIDI | PDF 等需要 ABC，钢琴 WAV 需要 MIDI；没有 MIDI 时取消“钢琴 WAV”；只有 MIDI 时取消 PDF／PNG／SVG。多个候选文件时手动指定 |
| 外部 MIDI 钢琴导出提示鼓轨／音高越界 | 当前不支持鼓轨，音高限定 MIDI 21～109；先在外部 MIDI 编辑工具中修正整个文件，再导出。仅切换声部不能绕过整文件校验 |
| 缺少某声部 | 该 MIDI 没有对应命名／识别的轨道；改选混合或已有声部，不代表软件已把原曲对应音轨删除 |
| 导入 LRC 后时间戳不见了 | 通用歌词导入会剥除时间戳，保留用于生成的文字。它不是把 LRC 导回歌词识别时间轴的功能 |
| MERT .npy 无法播放 | 它是数值特征文件；查看热图／相似度，或用支持 NumPy 的分析程序读取 |
| 日志有 deprecated／FutureWarning | 多为依赖接口弃用提示；先看任务是否完成、是否生成结果。出现 traceback、显存不足或任务明确失败时，再按实际错误处理 |

反馈问题时，提供：所在页面、操作步骤、相关参数、完整错误末段、环境信息、任务是否能再次复现。避免发送包含密钥的设置文件；需要示例时可使用一小段允许分享的素材。
